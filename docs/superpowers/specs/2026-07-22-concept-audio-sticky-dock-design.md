# Липкий мини-плеер аудио при скролле (Library) — дизайн

**Дата:** 2026-07-22
**Статус:** дизайн утверждён, готов к плану

## Цель

Когда на странице концепта пользователь листает вниз и обычный аудио-плеер (в шапке)
уезжает за верх экрана, дать управление озвучкой (пауза/продолжить/стоп, скорость,
индикатор секции) в **фиксированной нижней панели**. Панель появляется только во время
активного воспроизведения и исчезает при скролле вверх (плеер снова виден) или при
остановке. Чисто клиентская UI-надстройка над уже существующей TTS-фичей.

## Ключевые решения

- **Место — фиксированная нижняя панель** (как мини-плеер Spotify/YouTube). Не конфликтует
  со sticky-топбаром (`h-16 z-40`), удобно на мобилке.
- **Триггер — `!inView && (status === 'playing' || status === 'paused')`.** Панель видна,
  только когда инлайн-плеер вне экрана И идёт/на паузе озвучка. В `idle`/`unsupported` и
  когда инлайн-плеер виден — панели нет. «Играть» в панели = продолжить с паузы.
- **Детекция через IntersectionObserver**, без scroll-листенеров.
- **Одна модель состояния.** Панель переиспользует тот же `AudioPlayer` и тот же объект
  `speech` (один хук `useConceptSpeech` в `ConceptPage`) — это второй рендер контролов над
  общим состоянием, не второй плеер.
- **a11y:** когда панель показана, инлайн-плеер (за экраном) помечается `aria-hidden` —
  чтобы у скринридеров не было двух одинаковых наборов контролов и двойных `aria-live`.

## Область (scope)

- Generic-хук `useInView` (IntersectionObserver).
- Презентационный `AudioDock` (фиксированный нижний контейнер + slide-анимация + тот же
  `AudioPlayer`).
- Интеграция в `ConceptPage`: ref на обёртку инлайн-плеера, вычисление `docked`, рендер дока,
  `aria-hidden` на инлайн-плеере при показанном доке.
- Тесты на все три единицы.

**Вне области:** перетаскивание/сворачивание панели; кнопка jump-to-section в доке; показ
имени концепта; применение вне `ConceptPage`; изменение самой TTS-логики (`domain/tts/*`,
`useConceptSpeech`, `AudioPlayer` контролы) — не трогаем.

## Архитектура

### 1. `src/features/library/useInView.ts` — детекция видимости

Тонкая обёртка над IntersectionObserver, изолирует API. Без завязки на аудио.

```ts
export function useInView<T extends Element>(): { ref: RefObject<T>; inView: boolean };
```

- Создаёт `IntersectionObserver` (threshold 0) на элемент из `ref`, пишет `entry.isIntersecting`
  в состояние `inView`.
- Если `IntersectionObserver` отсутствует (например, SSR/старое окружение) — деградирует:
  `inView` остаётся `true` (док не всплывает — безопасный дефолт, фича просто выключена).
- Отписывается (`observer.disconnect()`) в cleanup эффекта и при смене элемента.

### 2. `src/features/library/AudioDock.tsx` — фиксированная нижняя панель

```ts
export function AudioDock({ speech, visible }: { speech: ConceptSpeech; visible: boolean }): JSX.Element | null;
```

- Если `speech.status === 'unsupported'` → `null` (наследуется от `AudioPlayer`, который сам
  так делает; но и `visible` в этом случае никогда не true).
- Фиксированный контейнер снизу: `fixed inset-x-0 bottom-0 z-40`, фон `bg-surface/80` +
  `backdrop-blur-xl`, верхний бордюр `border-t border-line`. Внутренний контент выровнен по
  колонке контента — **на десктопе левый отступ = ширина сайдбара** (`md:pl-[15.5rem]`,
  совпадает с `md:grid-cols-[15.5rem_1fr]` из `Layout`), паддинги как у `main`.
- Внутри — тот же `<AudioPlayer speech={speech} />`.
- Появление/уход: `visible` управляет `translate-y-full` → `translate-y-0` + `transition`.
  При `prefers-reduced-motion: reduce` — без трансформа (просто показ/скрытие). Когда
  `visible=false` — панель уведена за экран и `aria-hidden="true"` (или не рендерится).

### 3. Интеграция в `src/features/library/ConceptPage.tsx`

- `const { ref: playerRef, inView } = useInView<HTMLDivElement>();`
- Обернуть инлайн-`<AudioPlayer>` в `<div ref={playerRef} aria-hidden={docked || undefined}>`.
- `const docked = !inView && (speech.status === 'playing' || speech.status === 'paused');`
- В конце `<article>` отрендерить `<AudioDock speech={speech} visible={docked} />`.
- Инлайн-плеер и его логика подсветки/скролла — без изменений.

## Данные и поток

`useConceptSpeech` (единый источник состояния) → `AudioPlayer` (инлайн, в шапке) и тот же
`AudioPlayer` внутри `AudioDock`. `useInView` наблюдает обёртку инлайн-плеера → `inView`.
`docked = f(inView, speech.status)`. Никакого нового состояния воспроизведения не вводится.

## a11y

- Ровно один «активный» набор контролов для скринридеров: при `docked` инлайн получает
  `aria-hidden="true"` (он и так за экраном), объявления `aria-live` («секция N из M») идут
  только из панели.
- Кнопки/селектор в панели — те же доступные элементы из `AudioPlayer` (уже с `aria-label`).
- Анимация уважает `prefers-reduced-motion`.
- Фон панели полупрозрачный с blur — контраст текста/контролов остаётся на токенах,
  AA-инвариант проекта не нарушается (используем те же классы, что и топбар).

## Тесты

- **`useInView.test`** — мок `IntersectionObserver` (стаб конструктора, ручной вызов колбэка):
  `inView` меняется по `isIntersecting`; `disconnect` вызывается на unmount; без API `inView===true`.
- **`AudioDock.test`** — при `visible` рендерит контролы `AudioPlayer` (кнопка/скорость видимы);
  при `!visible` панель `aria-hidden`/отсутствует; при `status==='unsupported'` → `null`.
- **`ConceptPage` (dock)** — стабим `IntersectionObserver` (+ `scrollIntoView`); запускаем
  `play`; эмулируем «инлайн вне экрана» (колбэк IO `isIntersecting:false`) → нижняя панель
  появляется; эмулируем «виден» (`isIntersecting:true`) → панель исчезает; проверяем, что при
  показанной панели обёртка инлайн-плеера `aria-hidden`.

## Edge-cases

- `IntersectionObserver` отсутствует → `inView` фиксируется `true` → док никогда не всплывает,
  инлайн-плеер работает как прежде.
- Стоп/дочитано (`status → 'idle'`) при плеере вне экрана → `docked` становится `false`,
  панель уезжает.
- Смена концепта/языка (плеер останавливается — `useConceptSpeech` cleanup) → `status` не
  `playing/paused` → панель скрыта.
- Мобилка (нет сайдбара) → `md:pl-[15.5rem]` не применяется, панель full-width.

## Рассмотрено и отклонено

- **Полоса под топбаром (сверху):** ощущается как «плеер вернулся на место», но съедает
  вертикаль контента и визуально конфликтует со sticky-шапкой. Нижняя панель привычнее для
  аудио и не мешает чтению.
- **Плавающая пилюля в углу:** минимально навязчиво, но мало места под контролы+прогресс и
  перекрывает контент.
- **Показ панели всегда (даже в idle) при плеере вне экрана:** лишний постоянный хром при
  чтении без озвучки; привязали к активному воспроизведению.
- **scroll-листенер вместо IntersectionObserver:** дёргается на каждый кадр скролла,
  требует ручного троттлинга; IO эффективнее и проще.

## Критерии готовности

- При активной озвучке и уходе инлайн-плеера за верх экрана снизу появляется панель с
  рабочими play/pause/resume/stop, скоростью и индикатором «секция N из M».
- Скролл вверх (плеер снова виден) или стоп/дочитано → панель уезжает.
- В `idle`/`unsupported` панели нет; без `IntersectionObserver` фича тихо выключена.
- При показанной панели инлайн-плеер `aria-hidden`; нет двойных контролов/объявлений.
- Анимация уважает `prefers-reduced-motion`; на десктопе панель выровнена под колонку контента.
- Все новые и существующие тесты зелёные; TTS-логика (`domain/tts/*`, `useConceptSpeech`,
  контролы `AudioPlayer`) не изменена.
