# ArchMentor — Сравнение паттернов бок о бок (раздел «Сравнение»)

**Дата:** 2026-07-10
**Статус:** утверждён дизайн, готов к плану реализации
**Контекст:** приложение feature-complete, билингв RU/EN, clean-modern редизайн, 8 режимов на master и в проде (Dashboard, Course, Learn, Review, Quiz, Interview, Library, Progress). Каталог — 42 концепта; у каждого локализованные поля `definition/problem/solution/pros/cons/tradeoffs/whenToUse/whenNotToUse?/codeExample` и `related` (id похожих/путаемых концептов, валидируется на этапе импорта). Резолвер `src/content/localize.ts` (`useConcepts()`/`ConceptView`), рендер кода — `src/components/CodeBlock.tsx`. Стор Zustand+persist не содержит ничего для этой фичи и не изменяется.

## 1. Цель и рамки

Новый 9-й режим — экран **`/compare`**, где два выбранных концепта показаны бок о бок построчно, чтобы наглядно увидеть различия (Strategy vs State, Factory Method vs Abstract Factory и т.п.). Учит **применять и различать**, а не только узнавать. Полностью на существующих данных: без изменений схемы, контента и стора.

### Не входит (YAGNI)
- **Подбор паттерна по задаче** («какой паттерн под мою проблему») — отдельная механика с моделью «задача→паттерн», отдельная будущая спека.
- Сравнение **трёх и более** концептов одновременно — только пара.
- Diff-подсветка отличий, автоген «в чём разница» — показываем поля рядом, вывод делает пользователь.
- Изменения схемы/контента/стора; персист выбора между сессиями (кроме URL — см. §2).
- Ограничение пар одной категорией — разрешаем любой-с-любым (пресеты направляют к осмысленным парам).

## 2. Поведение / UX

- Маршрут `/compare` (пустой) и deep-link **`/compare/:a/:b`** (открывается сразу с парой; ссылка шарится).
- **Пустое состояние** (`/compare` без пары): два поисковых селектора + блок пресетов **«Часто путают»**.
- **Выбор пары:**
  - Два поисковых селектора (левый = A, правый = B), fuzzy-фильтр по имени/aka/tagline — как в Library/CommandPalette. Во втором селекторе тот же концепт, что выбран в первом, недоступен (нельзя сравнивать с самим собой).
  - Пресеты «часто путают» — кликабельные чипы из **взаимных** пар `related` (A ∈ related(B) И B ∈ related(A)); клик подставляет пару.
  - Любой выбор/пресет обновляет URL на `/compare/:a/:b` (через `navigate`), чтобы состояние жило в адресе и шарилось.
- **Раскладка сравнения** (обе пары выбраны):
  - Desktop: две колонки, выровненные по строкам-полям в порядке: **tagline, определение, проблема, решение, плюсы, минусы, trade-offs, когда применять, когда не стоит, пример кода**.
  - Шапка каждой колонки: имя концепта + грейд-бейдж + категория, ссылка «в библиотеку» на `/library/:id`.
  - Метки строк — из существующих ключей `concept.*` (definition/problem/solution/pros/cons/tradeoffs/whenToUse/whenNotToUse/codeExample).
  - Списочные поля (pros/cons/tradeoffs/whenToUse) рендерятся списками; `whenNotToUse` — только если есть у концепта (иначе пустая ячейка/пропуск строки, если нет ни у одного).
  - Код — через `CodeBlock`, в горизонтально-скроллящемся контейнере.
  - Раскладка построена как список секций-полей: у каждого поля своя метка (общая для пары) и под ней 2-колоночная сетка со значениями A и B. Desktop: две колонки рядом. Mobile (< md): сетка сворачивается в одну колонку, т.е. по каждому полю значение A, затем значение B (A и B одного поля остаются рядом — удобно для сравнения). Шапки-колонки с именами концептов остаются сверху (sticky не требуется).
- Некорректный id в URL (нет такого концепта) → трактуем как «не выбран» (показываем селекторы/пустое состояние), без падения.

## 4. Данные / состояние

- Источник — `useConcepts()` (локализованные `ConceptView`); выбранная пара — из URL-параметров `:a`/`:b`.
- **Никакого персиста и изменений стора.** Состояние UI (открытость выпадашки селектора, текст поиска) — локальный `useState`.
- Реактивность к языку: поля берутся из `useConcepts()` (подписан на `settings.lang`) — при смене языка колонки перелокализуются автоматически.

## 5. i18n

- `nav.compare`: «Сравнение» / «Compare»
- `compare.title`: «Сравнение паттернов» / «Compare patterns»
- `compare.selectA` / `compare.selectB`: плейсхолдеры селекторов («Первый концепт…»/«Второй концепт…» / «First concept…»/«Second concept…»)
- `compare.confusable`: «Часто путают» / «Commonly confused»
- `compare.emptyTitle` / `compare.emptyHint`: пустое состояние (выберите два концепта…)
- Метки полей — существующие `concept.*` (не дублировать).
- Обе локали, паритет ключей под существующим i18n-тестом.

## 6. Доступность

- Селекторы — доступные комбобоксы: `<input role="combobox">` + список `role="listbox"`/`option`, навигация с клавиатуры, `aria-label` из `compare.select*` (паттерн уже отработан в `CommandPalette`).
- Пресет-чипы и ссылки «в библиотеку» — настоящие `<button>`/`<Link>` с видимым фокус-рингом (`focus-visible:ring-accent`).
- Строки сравнения — семантическая разметка (заголовки полей ассоциированы со значениями); на desktop — сетка, на mobile — секции с заголовками.
- Контраст — только существующие токены (под `contrast.test.ts`); новых цветов-для-текста не вводим.

## 7. Тестирование

- **`selectConfusablePairs`**: взаимные пары выявляются; односторонние `related` игнорируются; нет дублей и перестановок; детерминированный порядок.
- **Компонент (smoke):** deep-link `/compare/<a>/<b>` (через `MemoryRouter`) рендерит имена и определения обоих концептов; клик по пресет-чипу приводит к рендеру пары; выбор во втором селекторе исключает уже выбранный слева.
- **Регрессия:** весь существующий набор зелёный; `tsc --noEmit` чист; сборка без предупреждений; билингв RU/EN; обе темы; mobile-раскладка (сетка полей сворачивается в одну колонку) не ломает горизонтальный скролл страницы (код — в своём `overflow-x`).

## 8. Критерии готовности

- Экран `/compare` доступен из сайдбара и ⌘K; deep-link `/compare/:a/:b` открывает пару.
- Два поисковых селектора + пресеты «часто путают» из `related`; нельзя выбрать концепт сам с собой.
- Две колонки бок о бок со всеми полями концепта; ссылки в библиотеку; на mobile — стек.
- Схема/контент/стор не изменены; новых зависимостей нет.
- `tsc` чист, все тесты зелёные (включая новый доменный и smoke), билингв, обе темы.
