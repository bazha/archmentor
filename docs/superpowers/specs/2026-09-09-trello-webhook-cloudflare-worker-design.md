# Trello-вебхук: self-hosted n8n на маке → Cloudflare Worker — дизайн

**Дата:** 2026-09-09
**Статус:** дизайн утверждён, готов к плану

## Цель

Убрать последнюю зависимость автоматики доски от включённого ноутбука.

Сейчас событийный путь «карточка → In Progress → запуск агента» идёт через ngrok-туннель в
n8n-контейнер на маке. Пока мак спит, Trello делает три ретрая (30с / 60с / 120с) и бросает
доставку — событие теряется молча, и карточка стартует только с часового cron-фолбэка.

При этом n8n у нас выродился в один HTTP-редирект с одним условием: вся логика (выбор карточки,
`claude:wip`, `needs-info`, диалог по комментариям) живёт в `.github/scripts/trello.sh` и работает
на состоянии доски, а не на payload'е вебхука. Поэтому на Cloudflare переезжает не «n8n», а
~50 строк кода: принять вебхук → отфильтровать → дёрнуть `workflow_dispatch`.

Побочная, но важная цель: вынести фильтр двойного срабатывания из GUI-ноды n8n в код под тестами.
Сейчас это выражение нельзя ни протестировать, ни увидеть в code review, и оно исчезает вместе с
Docker-волюмом.

## Проверенные факты Trello (не по памяти)

Источник: developer.atlassian.com/cloud/trello/guides/rest-api/webhooks/

- При создании вебхука Trello синхронно делает **HTTP HEAD** на `callbackURL`; если ответ не `200`,
  вебхук **не создаётся**. Хендлер обязан отвечать на HEAD.
- Битый SSL-сертификат на `callbackURL` тоже ломает создание (отсутствие сертификата — нет).
  `*.workers.dev` отдаёт валидный сертификат Cloudflare.
- При неудачной доставке — **3 ретрая с задержками 30с / 60с / 120с**, потом Trello бросает событие.
- Автоотключение вебхука требует одновременно 30 дней непрерывных неудач **и** 1000+ провальных
  доставок — то есть спящий мак вебхук не убивает. Проблема именно в потерянных событиях.
- Подпись `X-Trello-Webhook` — base64 от HMAC-SHA1 по конкатенации тела запроса и `callbackURL`,
  ключ — application secret. Мы её не используем (см. решение 3).

## Ключевые решения

1. **Тонкий stateless Worker, а не порт n8n.** Один `fetch`-хендлер. Никаких KV, Queues, Durable
   Objects, Cron Triggers. Дедупликация не нужна: от парного `updateCard` защищает фильтр, от
   одновременных запусков — `concurrency: trello-agent` в воркфлоу, от повторного взятия карточки —
   лейбл `claude:wip`.

2. **Домен не нужен.** `*.workers.dev` даёт бесплатный HTTPS-эндпоинт без DNS, зоны и Route.
   URL складывается как `https://<name из wrangler.toml>.<субдомен аккаунта>.workers.dev`.
   Субдомен выбирается один раз на аккаунт при первом деплое и считается постоянным (смена ломает
   все `workers.dev`-адреса аккаунта), поэтому берём нейтральный, по нику, а не по имени проекта:
   **`bazhanau`**, итого `https://trello-webhook.bazhanau.workers.dev`. Аккаунт Cloudflare уже создан
   (`bazhanau.arthur@gmail.com`), `wrangler login` пройден, `account_id` — в памяти проекта.
   Cloudflare Tunnel (старый «вариант C») отвергнут именно потому, что требовал бы домена.

3. **Аутентификация — секретный сегмент пути**, не проверка подписи. `POST /trello/<WEBHOOK_TOKEN>`,
   где токен — `openssl rand -hex 32`. Обоснование: HMAC-проверка требует Trello application secret
   (ещё один секрет и нетривиальная конкатенация «тело + callbackURL»), а выигрыш мал — лишний
   dispatch почти безвреден, потому что `select-and-claim` заново читает доску и на пустом месте
   выходит с «no eligible card». Сравнение пути — обычное строковое: тайминг-атака на 256 бит
   энтропии через публичный edge непрактична. Ротация токена = пересоздать вебхук с новым путём.

4. **Отдельный узкий PAT, не копия `GH_PAT`.** Fine-grained, только репозиторий `bazha/archmentor`,
   только `Actions: write` (+ `Metadata: read`, GitHub добавляет сам). Радиус поражения при утечке —
   «может запустить один воркфлоу». `GH_PAT` умеет пушить в master, и его копия в Worker'е
   означала бы, что утечка Worker'а = утечка записи в репозиторий.

5. **Исходники — в этом репозитории**, `workers/trello-webhook/`. Это единственный способ получить
   фильтр под `npm test` и под CI-гейтом; ради этого миграция и делается.

6. **Деплой руками, без автодеплоя.** Воркфлоу «push → deploy» потребовал бы Cloudflare API token с
   правом `workers:write` в GitHub Secrets — новая утекаемая сущность с правом переписать код,
   который дёргает наш же CI. Фильтр меняется раз в полгода; обмен плохой. Команда деплоя — в рунбук.

7. **`account_id` не коммитим.** Репозиторий публичный. Передаём через `CLOUDFLARE_ACCOUNT_ID`
   (значение — в рунбуке/памяти проекта). Это не секрет, но и светить незачем.

8. **Часовой cron в `trello-agent.yml` остаётся.** Он ничего не стоит и теперь страхует отказ
   Worker'а или GitHub API вместо «мак заснул».

## Архитектура

### 1. Раскладка

```
workers/trello-webhook/
  index.ts        — fetch-хендлер: маршрут, HEAD, проверка пути, dispatch
  filter.ts       — shouldDispatch(action, inProgressListId) — чистая функция, без Worker-глобалов
  filter.test.ts  — Vitest
  wrangler.toml   — конфиг деплоя (без account_id, без секретов)
  tsconfig.json   — свой, с типами Workers
```

Внутри существующего npm-проекта, без второго `package.json`: `wrangler` и типы Workers — в
root `devDependencies`. Корневой Vitest подхватит `filter.test.ts` дефолтным `include`
(`**/*.test.ts` вне `node_modules`), править `vite.config.ts` не нужно; `filter.ts` — чистый TS,
поэтому jsdom-окружение ему безразлично.

Корневой `tsc --noEmit` Worker не видит: в `tsconfig.json` стоит `include: ["src"]`. Поэтому у
Worker'а свой `tsconfig.json` и скрипт `"typecheck:worker": "tsc --noEmit -p workers/trello-webhook/tsconfig.json"`,
добавляемый шагом в `ci.yml`. Без этого
Worker формально в гите, но вне гейта — то есть та же непроверяемость, из-за которой мы уходим от
GUI-ноды.

### 2. Контракт хендлера

```
HEAD  любой путь              → 200            (требование Trello при создании вебхука)
POST  /trello/<WEBHOOK_TOKEN> → разбор + фильтр
всё остальное                 → 404
```

Исходы для `POST` по верному пути:

| ситуация | ответ | почему |
|---|---|---|
| фильтр сказал «нет» | `200` | Trello доволен, ретраев нет |
| dispatch удался (GitHub → `204`) | `200` | |
| dispatch упал (5xx, сеть) | `500` | Trello сделает свои 3 ретрая — короткий сбой GitHub API переживаем бесплатно, без собственной очереди |
| dispatch вернул `401`/`403` | `500` + явный лог «PAT истёк или лишён прав» | самый вероятный тихий отказ, см. «Эксплуатация» |
| тело не парсится / нет `action` | `200` + лог | ретраить нечего |

Dispatch: `POST https://api.github.com/repos/{GITHUB_REPO}/actions/workflows/{WORKFLOW_FILE}/dispatches`
с телом `{"ref": GIT_REF}`, заголовками `Authorization: Bearer <GH_DISPATCH_TOKEN>`,
`Accept: application/vnd.github+json`, `User-Agent: trello-webhook-worker`. Успех — `204`.

### 3. Фильтр

```ts
export function shouldDispatch(
  action: unknown,
  inProgressListId: string,
): { dispatch: boolean; reason: string }
```

Два правила, ровно как в n8n сейчас:

1. `action.type === 'updateCard'` **и** `action.data.listAfter?.id === inProgressListId`.
2. `action.type === 'commentCard'` **и** текст не начинается с `🤖` (маркер агента).

Всё остальное — `false`. Причина возвращается строкой: она идёт в лог и в сообщения тестов.

**Только `listAfter`, никогда `data.list.id`.** Одно перетаскивание карточки порождает два
`updateCard`-экшена (смена списка и подгонка `pos`), и `listAfter` есть только у первого;
`data.list.id` присутствует при любой правке карточки, уже лежащей в In Progress, и даёт ложные
срабатывания. Это самый дорого добытый факт в системе — он был выявлен и исправлен 2026-08-25.
Внимание: в `docs/superpowers/plans/2026-07-23-trello-agent-comment-dialogue.md:175` закоммичена
**старая, ошибочная** форма выражения с фолбэком `|| $json.action.data.list?.id`. Она исторический
артефакт; источником истины становится `filter.ts`. Копировать выражение из того плана нельзя.

Проверку «а лежит ли карточка в In Progress» для комментариев не делаем: `select-and-claim` всё
равно перечитывает доску и сам решает, кто подходит. Лишний dispatch стоит ~20 секунд раннера.

### 4. Конфиг и секреты

`wrangler.toml` (коммитится, публичен — только публичные значения):

```toml
name = "trello-webhook"
main = "index.ts"
compatibility_date = "2026-09-09"
workers_dev = true

[vars]
GITHUB_REPO   = "bazha/archmentor"
WORKFLOW_FILE = "trello-agent.yml"
GIT_REF       = "master"
```

Секреты — через `npx wrangler secret put <ИМЯ>` (шифруются на стороне Cloudflare, обратно не
читаются, только перезапись):

| секрет | значение | зачем |
|---|---|---|
| `GH_DISPATCH_TOKEN` | новый fine-grained PAT, срок 1 год | запуск `trello-agent.yml` |
| `TRELLO_INPROGRESS_LIST_ID` | id списка In Progress | вход фильтра |
| `WEBHOOK_TOKEN` | `openssl rand -hex 32` | секретный сегмент пути |

`TRELLO_INPROGRESS_LIST_ID` держим секретом для консистентности с GitHub Secrets, хотя настоящим
секретом он уже не является: id утёк в `docs/superpowers/plans/2026-07-23-…md` ещё в июле.
Ратифицировать эту утечку переносом id в публичный `wrangler.toml` не будем.

Trello key и token Worker'у не нужны вообще — он не обращается к Trello API. Это само по себе
сокращение поверхности против n8n, где Trello-кред лежал в SQLite-волюме на маке.

## Поток данных

```
Trello (вебхук на доску)
  → POST https://trello-webhook.<субдомен>.workers.dev/trello/<WEBHOOK_TOKEN>
  → Worker: проверка пути → shouldDispatch(action, INPROGRESS_LIST_ID)
  → POST .../actions/workflows/trello-agent.yml/dispatches  {"ref":"master"}
  → GitHub Actions: trello-agent.yml  (без изменений)
      → .github/scripts/trello.sh select-and-claim  (без изменений)
      → claude-code-action → ветка + коммит → PR открывает CI под GH_PAT
      → trello.sh finalize
  → [PR смержен] → trello-done.yml → карточка в Done  (вне этой миграции, уже нативный)
```

## Порядок миграции (весь риск — здесь)

1. Первый деплой: `npx wrangler deploy` — Cloudflare спросит workers.dev-субдомен, создаст Worker и
   напечатает URL. Между деплоем и шагом 2 эндпоинт безопасен: `WEBHOOK_TOKEN` не задан, сравнение
   пути не проходит ни с чем, всё кроме HEAD получает `404`.
2. `wrangler secret put` × 3.
3. `curl -sI <URL с секретным путём>` → `200`. **До** удаления старого вебхука: если Worker не
   отдаёт 200, Trello откажется создавать новый, и мы останемся без событийного пути.
4. Инвентаризация вебхуков (глазами не считаем):
   `curl -s "https://api.trello.com/1/tokens/$TRELLO_TOKEN/webhooks?key=$TRELLO_KEY" | jq -r '.[] | "\(.id)  \(.callbackURL)  active=\(.active)"'`
   Ожидаем одну запись на ngrok-домен.
5. `cd ~/docker/n8n && docker compose stop` — без `down`, без `-v`.
6. `DELETE /1/webhooks/<id>` — старый вебхук.
7. `POST /1/webhooks` — новый: `callbackURL=<URL Worker'а с секретным путём>`, `idModel=<id доски —
   берётся из памяти проекта, в репозиторий не пишется>`,
   `description=trello-agent via cloudflare worker`.
8. Проверить `jq 'length'` → `1`.

Порядок «сначала удалить, потом создать» обязателен: два живых вебхука на одну доску дают два
dispatch'а на одно перетаскивание. Провал в покрытии между шагами 6 и 7 — секунды, и он прикрыт
часовым cron.

## Тестирование

**Юнит (Vitest, фикстуры — реальные payload'ы Trello, урезанные до нужных полей):**

- перетаскивание в In Progress → `dispatch: true`
- парный pos-only `updateCard` того же перетаскивания → `false`
- правка карточки, уже лежащей в In Progress → `false` ← регресс на `data.list.id`
- перемещение в любой другой список → `false`
- `commentCard` от пользователя → `true`
- `commentCard`, начинающийся с `🤖` → `false`
- мусорный payload без `data` / без `type` → `false`, без исключения

**Локально, не запуская агента:** `npx wrangler dev` + `curl` с фикстурой. В локальном окружении
`GH_DISPATCH_TOKEN` не задаём — фильтр отработает по-настоящему, dispatch получит `401`, и в логах
видно «маршрут и фильтр верны», а реальный запуск агента не происходит.

**Приёмка на живой доске (все три обязательны):**

- *Позитивный:* карточка → In Progress; в течение секунд `gh run list --workflow=trello-agent.yml`
  показывает **ровно один** запуск. Два запуска = фильтр по `listAfter` не работает. Дальше обычный
  цикл до Done с одним `🤖 ✅` комментарием.
- *Негативный (главный):* переименовать карточку, уже лежащую в In Progress → новых запусков нет.
  Здесь проверяется настоящий payload Trello, а не наша фикстура.
- *Диалоговый:* ответ комментарием на `needs-info`-карточку → запуск есть; коммент агента с `🤖` →
  запуска нет.

## Снос (только после приёмки, в два шага)

Шаг 1, сразу: `docker compose down` — **без `-v`**, волюм `n8n_data` остаётся.

И **до** удаления каталога — вынести Trello-креды:
`mkdir -p ~/.config/trello && cp ~/docker/n8n/trello.env ~/.config/trello/env && chmod 600 ~/.config/trello/env`.
В GitHub Secrets токен write-only, и `~/docker/n8n/trello.env` — единственная копия на руках.
Потерять её означает перевыпуск токена, а перевыпуск убивает все вебхуки старого токена, то есть
саму автоматику.

Шаг 2, через неделю нормальной работы: `docker compose down -v`, удалить `~/docker/n8n`, снять
образы, освободить закреплённый ngrok-домен, удалить ngrok-аккаунт. Заодно удалить аккаунт n8n Cloud
(держался как rollback до 2026-09-01) — после миграции n8n не остаётся ни в каком виде.

**Откат** до шага 2 стоит две команды: `docker compose up -d` + перерегистрировать вебхук на
ngrok-домен. После `down -v` откат невозможен: вместе с волюмом уходят креды и сам воркфлоу n8n.

## Эксплуатация и наблюдаемость

Вкладки Executions с историей запусков и входными payload'ами больше не будет — это честная
деградация. Остаётся `npx wrangler tail` (живой стрим, только пока смотришь) и метрики в дашборде;
Workers Logs включим и проверим, что даёт free tier. Поэтому Worker логирует осмысленно:
`action.type`, id карточки, решение фильтра с причиной, код ответа GitHub.

**Мина: PAT истекает через год.** По истечении Worker начнёт молча получать `401`, а часовой cron
продолжит подбирать карточки — поломка будет выглядеть не как поломка, а как «стало медленнее».
Поэтому: дата истечения фиксируется в памяти проекта, а Worker на `401`/`403` пишет в лог явное
сообщение. GitHub App с неистекающим installation-токеном был бы правильнее, но это отдельная
сущность с приватным ключом и обменом JWT ради одного POST'а — несоразмерно.

Деплой: `CLOUDFLARE_ACCOUNT_ID=<account_id из памяти проекта> npx wrangler deploy --config workers/trello-webhook/wrangler.toml`.

## Правки в репозитории

Кода приложения миграция не касается.

- `.github/workflows/trello-agent.yml` — две строки комментария в шапке (`n8n triggers this` →
  Worker) и переформулировка роли cron: страхует отказ Worker'а или GitHub API, а не спящий мак.
- `.github/workflows/ci.yml` — шаг `typecheck:worker`.
- `package.json` — два devDependency (`wrangler`, типы Workers) и скрипт `typecheck:worker`.
- Память проекта (файл про n8n) — перезаписывается целиком: стек, URL вебхука, где секреты, дата
  истечения PAT, команда деплоя.

## Edge-cases

**Повторный dispatch из-за потерянного ответа.** Ретраи Trello присылают тот же payload. Если
GitHub вернул 5xx и на ретрае ответил `204` — dispatch один, всё хорошо. Но если dispatch на самом
деле прошёл, а ответ потерялся (таймаут, сбой на edge), ретрай запустит воркфлоу второй раз.
`concurrency: trello-agent` с `cancel-in-progress: false` не отбросит второй запуск, а поставит его
в очередь — и он найдёт карточку уже под лейблом `claude:wip`, то есть выйдет с «no eligible card».
Цена — ~20 секунд раннера, двойного взятия карточки не происходит. Поэтому выбор «отдавать 500 ради
бесплатных ретраев» безопасен, хотя на первый взгляд выглядит иначе.

**Окружение Vitest для теста фильтра — проверить, а не предполагать.** Корневой конфиг задаёт
`environment: 'jsdom'` и глобальный `setupFiles: ['./src/test-setup.ts']`, и они применятся и к
`workers/trello-webhook/filter.test.ts`. Первым шагом плана — положить пустышку-тест и прогнать
`npm test`: убедиться, что дефолтный `include` действительно резолвится от корня проекта, а
`src/test-setup.ts` не падает вне контекста приложения. Если что-то из этого не так, лечится либо
докблоком `@vitest-environment node` в файле теста, либо точечным override в `vite.config.ts` —
выбор делается по факту. До этой проверки утверждение «править `vite.config.ts` не нужно» остаётся
предположением.

**Карточку перевели в In Progress, пока Worker деплоится.** Событие теряется (Trello отретраит и
бросит), карточку подберёт часовой cron. Деплой занимает секунды, окно ничтожно.

**Несколько карточек переведены разом.** Каждая даёт свой dispatch, `concurrency` выстраивает их в
очередь, `select-and-claim` берёт по одной в порядке `pos`. Поведение то же, что сейчас с n8n.

## Границы (v1)

Сознательно **не** делаем:

- Никакой логики Trello внутри Worker'а: выбор карточки, лейблы, комментарии остаются в `trello.sh`.
- Никакого автодеплоя (решение 6).
- Никакой проверки подписи `X-Trello-Webhook` (решение 3).
- Никакого KV/Queues/Durable Objects и своей очереди ретраев — ретраи Trello плюс часовой cron.

## Критерии готовности

1. `npm test` зелёный, включая все семь кейсов фильтра; `npm run typecheck:worker` зелёный; оба под
   CI-гейтом на pull_request.
2. Worker задеплоен, отвечает `200` на HEAD и `404` на неверный путь.
3. Trello-вебхуков на доску ровно один, смотрит на Worker, `active=true`.
4. Все три сценария приёмки пройдены, включая негативный.
5. Контейнеры остановлены, `trello.env` скопирован в `~/.config/trello/env`.
6. Мак можно выключить — карточка, переведённая в In Progress с телефона, запускает агента.
