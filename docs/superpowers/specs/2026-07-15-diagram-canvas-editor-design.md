# Diagram Builder: канва как полноценный редактор — дизайн

**Дата:** 2026-07-15
**Статус:** дизайн утверждён, готов к плану
**Расширяет:** `docs/superpowers/specs/2026-07-15-diagram-builder-design.md` (режим `/diagram`, на master)

## Цель

Углубить канву режима `/diagram`: из «показ нод + рисование связей» сделать полноценный
редактор — **перетаскивание нод, добавление перетаскиванием из палитры на канву, удаление
на канве** (видимая кнопка-крестик на ноде + клавиша Delete). Списочный конструктор
(доступное с клавиатуры ядро) и домен не меняются.

## Область (scope)

- Перетаскивание нод по канве; позиции переживают переключение список↔канва.
- Drag-and-drop добавление: компонент из палитры → на канву в точку броска.
- Удаление на канве: видимая кнопка-крестик на ноде + Delete/Backspace для выделенного;
  удаление рёбер (Delete на выделенном ребре).
- Минимальный кастомный узел (имя + крестик + ручки), без иконок по типу.

Вне области: кастомные иконки-ноды по типу компонента; персист позиций в localStorage;
подписи рёбер; изменения домена/валидации; изменения списочного конструктора.

## Ключевое решение — где живут позиции

Позиции нод (x/y) — **забота view, не домена**: `validate` их игнорирует. Карта
`positions: Record<nodeId, {x, y}>` поднимается в `ScenarioBuilder` (родитель), чтобы:

- переживать переключение список↔канва (обе вьюхи делят одну карту),
- заполняться при любом добавлении ноды (кнопка списка, клик палитры, drop): **drop** берёт
  точку броска (screen→flow координаты), остальные — следующий слот сетки.

Хранится **в памяти сессии** — как и сам собираемый `Diagram` (он не персистится;
персистится только прохождение сценария). Удаление ноды → её запись из `positions`
выбрасывается.

## Архитектура по единицам

### 1. Домен — `src/domain/diagram/`

- **Без изменений** в `types.ts`/`validate.ts`/`edit.ts`. `Diagram` остаётся `{nodes, edges}`;
  позиции в него не попадают. `removeNode` уже чистит инцидентные рёбра.
- **Новый чистый помощник** `src/domain/diagram/positions.ts`:

  ```ts
  export interface XY { x: number; y: number }
  /** Детерминированная позиция для index-й ноды по сетке (для не-drop добавлений). */
  export function gridSlot(index: number): XY;
  ```

  Чистая, тестируемая; выносит позиционную математику из компонента.

### 2. Кастомный узел + канва — `src/features/diagram/CanvasBuilder.tsx`

**Минимальный кастомный узел** `ComponentNode` (модульного уровня, чтобы `nodeTypes` был
стабильной ссылкой):

- Рендерит локализованное имя компонента + **видимую кнопку-крестик** «удалить» (`aria-label`
  «Убрать: {имя}»), вызывающую `data.onDelete()`.
- Скрытые `Handle` (target сверху, source снизу) для рёбер, `isConnectable` включён (соединение
  перетаскиванием между ручками остаётся).
- Обработчик удаления передаётся через `data` (`data.onDelete = () => onRemoveNode(id)`), чтобы
  `nodeTypes` оставался модульным/стабильным; сам узел без иконок по типу (только имя + крестик).
- Стили — существующие семантические токены (тема наследуется).

**Канва:**

- Ноды строятся из `diagram.nodes` + `positions` (+ `data: { label, onDelete }`);
  `nodesDraggable`, `elementsSelectable`, `colorMode={theme}` (как сейчас).
- `onNodesChange` — применяет **только** изменения типа `position` обратно в родительскую
  карту `positions` (перетаскивание); остальные изменения игнорируются (существование/тип
  нод — из домена).
- `onConnect` → `addEdge` (как сейчас).
- `onNodesDelete` → `onRemoveNode(id)`; `onEdgesDelete` → `onDisconnect(from, to)`.
  Крестик на ноде вызывает тот же `onRemoveNode`. Delete/Backspace работают через RF для
  выделенного элемента; подсказка «Del — удалить выбранное».
- **Drop из палитры:** элементы палитры получают `draggable` + `onDragStart`
  (`dataTransfer` с типом компонента); обёртка канвы — `onDragOver` (preventDefault) и
  `onDrop`: конвертирует screen→flow координаты через RF-инстанс (пойманный в `onInit`) и
  вызывает `onAdd(type, dropPos)`. Клик по палитре остаётся (добавляет в авто-слот).

### 3. `ScenarioBuilder` — `src/features/diagram/Diagram.tsx`

- Владеет `positions` (state) + счётчиком слотов. Существующий `add` расширяется
  необязательной позицией: `add(type, at?: XY)` — при `at` кладёт туда, иначе `gridSlot(next)`.
  `rmNode` дополнительно удаляет запись из `positions`.
- Прокидывает в `CanvasBuilder`: `diagram`, `positions`, `onAdd`, `onRemoveNode`,
  `onConnect`, `onDisconnect`, `onMove(id, xy)` (для `onNodesChange`).
- Списочный конструктор получает те же `add/rmNode` (без позиций — позиция назначается в
  `add` автоматически). Поведение списка не меняется.

### 4. a11y

Списочный конструктор — полностью доступное с клавиатуры ядро (не меняется): добавить/удалить/
соединить доступно там. Канва получает mouse-first редактирование (drag/drop, крестик) —
усиление, не единственный путь. Крестик на ноде — реальный `<button>` с `aria-label`;
Delete-клавиша работает для клавиатурных пользователей на канве.

### 5. Тесты

- **`src/domain/diagram/positions.test.ts`** — `gridSlot`: детерминизм (тот же index → та же
  точка), разные index → разные точки, разумный шаг сетки.
- **Домен** — без новых тестов (`edit.ts` уже покрыт; `removeNode` дропает рёбра).
- **Списочный смоук-тест** `Diagram.test.tsx` — остаётся зелёным (список — дефолтная вьюха,
  не затронут).
- **Интеракция канвы** (drag/drop/delete-крестик) — React Flow в jsdom не тестируем (нужны
  layout/ResizeObserver), как и текущая канва; проверяется в браузере (CDP): добавить drag'ом
  из палитры, подвигать ноду, соединить, удалить крестиком и Delete, переключить список↔канва
  (позиции сохранились), тёмная/светлая тема.

## Рассмотрено и отклонено

- **Кастомные иконки-ноды по типу** — вне выбора пользователя (визуальная полировка); узел
  минимальный (имя + крестик).
- **Персист позиций в localStorage** — YAGNI: сам собираемый диаграмма не персистится.
- **Подписи рёбер** — концы уже типизированы; лишний шум.
- **Только Delete-клавиша без крестика** — отклонено пользователем (нужна видимая кнопка).

## Критерии готовности

- На канве: ноды перетаскиваются; компонент можно добавить перетаскиванием из палитры в точку;
  нода удаляется видимым крестиком и клавишей Delete; ребро удаляется Delete; соединение
  перетаскиванием между ручками работает.
- Позиции переживают переключение список↔канва в рамках сессии.
- Домен и списочный конструктор не изменены; `validate`/прохождение работают как раньше.
- `gridSlot` покрыт тестом; все существующие тесты зелёные; tsc и build чистые; канва
  проверена в браузере (тёмная/светлая).
