# Diagram Builder: объяснения «почему» в отчёте — дизайн

**Дата:** 2026-07-15
**Статус:** дизайн утверждён, готов к плану
**Расширяет:** `/diagram` (Diagram Builder), на master.

## Цель

Под каждой строкой отчёта ✓/⚠/✗ показывать короткое объяснение — рационал ограничения
(«зачем оно»). Превращает проверку в урок: у пройденного пункта — «почему это верно», у
проваленного — «почему важно». Объяснения пишутся для **ключевых** (нетривиальных)
ограничений; очевидные остаются без под-текста.

## Область (scope)

- Опциональное поле `explain: Localized` на ограничениях сценария (контент).
- Объяснения (ru+en) для нетривиальных ограничений 8 сценариев.
- Рендер объяснения под строкой отчёта, независимо от статуса.

Вне области: изменения домена/валидации; объяснения для всех ограничений (только ключевые);
объяснения в diff/списке/каком-либо ещё месте кроме построчного отчёта.

## Ключевое решение

Объяснение — это **рационал ограничения** (одинаков независимо от того, выполнено оно или
нет), поэтому живёт на самом ограничении в контенте и показывается на его строке при любом
статусе. Домен остаётся чистым: `explain` — контент (`Localized`), в валидацию/`CheckResult`
не входит; отчёт берёт объяснение из контента по индексу (`results[i]` ↔ `constraints[i]`,
т.к. `validate = constraints.map(checkOne)`).

## Архитектура по единицам

### 1. Контент — `src/content/diagram.ts`

- В `ConstraintSchema` (Zod discriminated union) добавить к **каждому** варианту опциональное
  поле `explain: LocalizedSchema.optional()`. Тип `Scenario`/`Constraint` (через `z.infer`)
  получает необязательное `explain`.
- Структурная совместимость с доменом: доменный `Constraint` (в `src/domain/diagram/types.ts`)
  поля `explain` не имеет; контентный тип — надмножество (лишнее опциональное поле), поэтому
  `validate(diagram, scenario.constraints)` по-прежнему типобезопасен (домен просто игнорирует
  `explain`).
- `validateScenarios` **не меняется** (поле опционально; кросс-проверок для `explain` не нужно).
- Автор добавляет `explain` (ru+en, непустые) к **нетривиальным** ограничениям каждого из 8
  сценариев: кэш (`required-edge …→cache`), хранилище (`any-of [sql,nosql]`), `between`
  (rate-limiter между client/api; message-queue между api/worker), `forbidden-node`
  (message-queue в url-shortener), CDN (`required-edge …→cdn`). Очевидные (`required-node
  client`/`api-server`) — без `explain`.

### 2. Рендеринг — `src/features/diagram/Report.tsx`

- `Report` получает новый **опциональный** проп `explanations?: (string | undefined)[]`
  (параллельно `results`). Под каждой строкой результата, если `explanations[i]` задано —
  мелкий приглушённый под-текст (`text-xs text-muted`). Показывается при любом статусе.
- Обратная совместимость: без `explanations` (или с `undefined` элементами) поведение как
  сейчас — просто нет под-текста. Существующие вызовы/тесты не ломаются.

### 3. Встройка — `src/features/diagram/Diagram.tsx` (`ScenarioBuilder`)

- В блоке отчёта строить `const explanations = scenario.constraints.map((c) => c.explain?.[lang])`
  и передавать в `<Report results={results} explanations={explanations} />`. `lang` уже
  доступен в компоненте.

### 4. Домен

Без изменений. `explain` в логику не входит; `validate`/`isPassed`/`CheckResult` не трогаем.

## Тесты

- **Контент** `src/content/diagram.test.ts` (дополнить): где `explain` задан — это валидный
  `{ru, en}` с непустыми строками; Zod-валидация проходит (поле опционально); минимум 1
  объяснение присутствует (напр. в url-shortener) — фиксирует, что фича реально наполнена.
- **`Report`** `src/features/diagram/Report.test.tsx` (новый; компонент чистый, не React Flow):
  рендерит под-текст объяснения, когда `explanations[i]` задано; не рендерит, когда `undefined`
  или проп не передан.
- Существующие тесты зелёные (Report обратно совместим; смоук-тест экрана не затронут).

## Рассмотрено и отклонено

- **Хранить `explain` в домене / `CheckResult`** — домен не должен нести `Localized`-контент;
  рендер берёт объяснение из контента по индексу.
- **Объяснять все ~40 ограничений** — шум на очевидных; выбрано «ключевые, опционально».
- **Показывать объяснение только на ⚠/✗** — рационал ограничения полезен и на ✓
  (подкрепление); показываем при любом статусе.

## Критерии готовности

- В отчёте под строками ключевых ограничений виден короткий разбор «почему» (ru+en), при
  любом статусе; очевидные ограничения — без под-текста.
- Домен/валидация/список/diff не изменены; `Report` обратно совместим.
- Контент-тест валидирует `explain` где задан; новый `Report`-тест покрывает рендер; все
  существующие тесты зелёные; tsc и build чистые.
