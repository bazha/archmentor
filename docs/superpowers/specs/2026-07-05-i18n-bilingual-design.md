# ArchMentor — билингвальность (RU/EN)

**Дата:** 2026-07-05
**Статус:** утверждён дизайн, готов к плану реализации
**Предшествующее:** приложение feature-complete (Фазы 1–3 на master, задеплоено). Сейчас UI и объяснения — на русском, имена паттернов/термины — на английском.

## 1. Цель и рамки

Сделать приложение полностью двуязычным (RU/EN): и интерфейс, и весь учебный контент (42 концепта + 77 вопросов). Пользователь переключает язык тумблером; выбор сохраняется. Новому посетителю язык определяется по браузеру.

Это осознанное расширение рамок: в исходной спеке мультиязычность контента была вынесена за скобки (YAGNI на старте). Теперь она в скоупе.

### Не входит (YAGNI)
- Третий язык / инфраструктура под произвольные локали — только `ru` и `en`.
- Внешняя i18n-библиотека (i18next и пр.) — свой лёгкий каркас, без новых зависимостей.
- Локализация дат/чисел (`Intl`) — в UI нет форматированных дат.
- Локализация `tags` — они не рендерятся в UI.
- Разные URL на язык (`/en/...`) — язык это состояние, не маршрут.

## 2. Языковая ось

- `type Lang = 'ru' | 'en'` (`src/i18n/lang.ts`).
- `detectLang(): Lang` — из `navigator.language`: `startsWith('ru')` → `'ru'`, иначе `'en'`. Безопасно к отсутствию `navigator` (fallback `'en'`).
- В сторе: `settings.lang: Lang` (рядом с `settings.theme`), персистится существующим механизмом (`partialize` уже сохраняет весь `settings`). Дефолт в `initialData()` = `detectLang()`; персистированное значение (если есть) перебивает при гидратации.
- FOUC-скрипт НЕ нужен: смена текста при гидратации не даёт визуальной вспышки не того цвета (в отличие от темы), а zustand-persist с синхронным localStorage гидратируется до первого рендера.

## 3. i18n-каркас для UI

Свой минималистичный каркас (без зависимостей):

- **`src/i18n/messages.ts`** — `export const messages: Record<Lang, Record<MessageKey, string>>`. Ключи покрывают все ~55 UI-строк (навигация, заголовки экранов, кнопки, метки статистики, подсказки, пустые состояния, aria-label тумблеров и поиска). `MessageKey` — union строковых литералов (типобезопасность ключей).
- **`src/i18n/useT.ts`** — `useT()` берёт `lang` из стора и возвращает `t(key: MessageKey, vars?: Record<string, string | number>): string`. Интерполяция плейсхолдеров вида `{n}` простым `replace` (для «{n} / {total}», «осталось: {n}», «рекорд: {n}», «Результат: {c} / {t}», «из {n}», «{grade} — освоено {m}/{t}» и т.п.).
- Захардкоженный русский в 12 компонентах (`Layout`, `ErrorBoundary`, `Dashboard`, `Learn`, `Review`, `Quiz`, `Library`, `ConceptCard`, `ConceptPage`, `Progress`, `FlipCard`, `ThemeToggle`) заменяется на `t(...)`.
- **`CATEGORY_LABEL`** становится локализованной картой `Record<Lang, Record<Category, string>>` в `src/lib/labels.ts` (симметрично существующему `GRADE_LABEL`): `Порождающие`→`Creational`, `Структурные`→`Structural`, `Поведенческие`→`Behavioral`, `Архитектурные стили`→`Architecture styles`, `SOLID`/`Trade-offs` — без изменений. **`GRADE_LABEL`** уже английский — остаётся общим для обоих языков.
- **`src/components/LanguageToggle.tsx`** — кнопка-переключатель RU/EN в шапке рядом с `ThemeToggle`; вызывает `setSettings({ lang })`; `aria-label` + `aria-pressed`/`aria-current`. Доступное имя и focus-ring как у `ThemeToggle`.

## 4. Модель данных контента (inline-локализация)

Замороженная схема получает локализованные типы:

```ts
type Localized = { ru: string; en: string };
type LocalizedList = { ru: string[]; en: string[] };
```

**Concept** — локализуются: `tagline`, `definition`, `problem`, `solution` (`Localized`); `pros`, `cons`, `tradeoffs`, `whenToUse`, `whenNotToUse?` (`LocalizedList`); `codeExample.code` (`Localized` — комментарии в коде переводятся). **Общие (не локализуются):** `id`, `name`, `aka`, `category`, `grade`, `related`, `tags`.

**Question** — локализуются: `prompt`, `explanation` (`Localized`); `options` (`LocalizedList`; для `identify-pattern` `en` совпадает с `ru` — это английские имена паттернов); `code?` (`Localized`). **Общие:** `id`, `type`, `category`, `grade`, `correctIndex`, `conceptId`.

`LocalizedList` для `options`: длины `ru` и `en` обязаны совпадать (иначе `correctIndex` разъедется) — проверяется в `validateContent`.

**Резолвер** `src/content/localize.ts`:
- `type ConceptView` / `QuestionView` — та же форма, что старые плоские `Concept`/`Question` (строки вместо `Localized`).
- `localizeConcept(c: Concept, lang: Lang): ConceptView`, `localizeQuestion(q: Question, lang: Lang): QuestionView`.
- Хуки `useConcepts(): ConceptView[]`, `useConcept(id): ConceptView | undefined`, `useQuestions(): QuestionView[]` — берут `lang` из стора, резолвят. Компоненты потребляют `*View` и читают поля как раньше — билингв-сложность изолирована в контент-слое; JSX меняется минимально (меняется источник данных, не чтение полей).

**Стор-селекторы не меняются:** `selectGradeProgress`, `selectReviewQueue`, `isMastered` и т.п. читают только общие поля (`id`, `category`, `grade`) и продолжают работать с сырыми `Concept[]` (`concepts` из `index.ts`). Локализация нужна только там, где отображается проза, — эти места переходят на `*View`-хуки.

**Отвергнутые альтернативы:** параллельные файлы `concepts/{ru,en}/*` (риск рассинхрона, дублирование, битьё кросс-ссылок `related`); внешняя карта переводов по `id`+поле (расфокус, легко потерять поле, отрыв перевода от структуры).

## 5. Миграция существующего контента

Смена схемы ломает текущий контент (плоские RU-строки), поэтому мигрируются все 42 концепта + 77 вопросов за один шаг, механически:
- Скриптовый трансформ (Node/Python) читает существующие `src/content/concepts/*.ts` и `questions.ts` и переписывает каждую RU-строку в `{ ru: <текущее>, en: <текущее> }` (для массивов — `{ ru: [...], en: [...] }`), сохраняя стиль (`code` как `[...].join('\n')`).
- `en` — плейсхолдер-копия RU. После миграции схема валидна, приложение работает, EN-режим временно показывает русский. Реальные EN приходят в Фазе B.
- Валидация round-trip: значения `ru` после миграции побайтово равны исходным (как в Фазе 2).

## 6. Фазирование (два плана, последовательно)

**Фаза A — каркас + UI + модель данных + миграция.**
`Lang`/`detectLang`, `settings.lang` + дефолт, `LanguageToggle`, каталог сообщений, перевод всех UI-строк, локализованный `CATEGORY_LABEL`; локализованная схема, механическая миграция всего контента (en=плейсхолдер), резолвер + хуки, подключение компонентов. Критерий готовности: UI полностью двуязычен, переключатель работает и сохраняется, контент в обоих режимах показывает RU (EN=плейсхолдер), tsc чист, все тесты зелёные, сборка без предупреждений.

**Фаза B — генерация EN-контента.**
Workflow-fan-out (как Фаза 2): агент на концепт → перевод локализованных полей на английский с опорой на канон (GoF/Gamma, Fowler, R.C. Martin — для этих понятий английский исходный, проверка = верность канону + точность передачи смысла RU-оригинала) → adversarial-проверка → замена `en`-плейсхолдеров. Код переводится только в комментариях (сам код идентичен между `ru`/`en`). Всё проходит zod-валидацию.

## 7. Тестирование

- **Резолвер (`localize.ts`):** `localizeConcept`/`localizeQuestion` для обоих языков дают правильный срез; для `options` длины `ru`/`en` равны и `correctIndex` в диапазоне.
- **i18n:** `t(key, vars)` интерполирует `{...}`; тест-страж — множества ключей `messages.ru` и `messages.en` идентичны (нет пропущенных переводов); `detectLang` (ru-браузер→`ru`, иначе→`en`, отсутствие `navigator`→`en`).
- **Стор:** смена `lang` через `setSettings` персистится; дефолт из `detectLang`.
- **Компоненты:** существующие тесты (ассертят русский) переводятся на явную установку `lang` в сторе перед рендером + проверку через каталог/резолвер; добавляется по одному EN-рендер-тесту на ключевые экраны (Library, ConceptPage, Quiz).
- **Контент-валидация:** `validateContent` дополняется проверкой равенства длин `options.ru`/`options.en`.
- **Фаза B:** zod-валидация полного набора + тест-страж, что `en`-поля не остались равными `ru`-плейсхолдерам (за исключением намеренно общих — `identify-pattern` options).

## 8. Критерии готовности (обе фазы)

- Тумблер RU/EN переключает весь интерфейс И весь контент; выбор сохраняется между перезагрузками; новому посетителю язык определяется по браузеру.
- Ни одной захардкоженной русской строки в UI-компонентах (все через `t`).
- EN-контент канон-корректен и полон (нет остаточных RU-плейсхолдеров).
- `tsc --noEmit` чист; все тесты зелёные; `npm run build` без предупреждений; обе темы × оба языка выглядят корректно.
