# Diagram Builder: визуальный diff с эталоном + стикеры на канве — дизайн

**Дата:** 2026-07-15
**Статус:** дизайн утверждён, готов к плану
**Расширяет:** `/diagram` (Diagram Builder), спеки `2026-07-15-diagram-builder-design.md` и
`2026-07-15-diagram-canvas-editor-design.md` (на master).

## Цель

Два независимых углубления канвы `/diagram`:

- **Юнит A — визуальный diff с эталоном** (фаза отчёта): после сабмита показать «Твою схему»
  и «Эталон» двумя read-only канвами бок о бок, подсветив совпадения / лишнее / недостающее.
- **Юнит B — стикеры на канве** (фаза сборки): свободные текстовые заметки-аннотации в стиле
  n8n — добавить, редактировать инлайн, перетаскивать, удалять.

## Важная рамка (diff)

Эталон сценария — **один из** валидных вариантов: грейдинг по ограничениям намеренно
пропускает корректные альтернативы. Поэтому визуальный diff **иллюстративный** («как твоя
схема соотносится с образцом»), а не «список ошибок». Источник истины по корректности —
построчный отчёт `✓/⚠/✗` (остаётся без изменений). Цвета diff нейтральные: **совпало = good**,
**«в эталоне есть, у тебя нет» = приглушённо/пунктир**, **«у тебя есть, в эталоне нет» =
info** (НЕ красный — лишнее ≠ неверно).

## Область (scope)

- Юнит A: чистая функция diff + read-only канва diff, встроенная в блок отчёта вместо
  текущего текстового списка рёбер эталона.
- Юнит B: состояние заметок (в памяти сессии) + кастомный узел-стикер + интеграция в
  `CanvasBuilder`; кнопка «+ Заметка».
- Билингв (ru/en), тёмная/светлая тема.

Вне области: наложение эталона на одну канву; красный цвет для «лишнего»; персист
стикеров/позиций в localStorage; resize стикеров; изменения домена `Diagram`/валидации;
изменения списочного конструктора; стикеры в списке/в diff/в сабмите.

## Архитектура по единицам

### Юнит A — визуальный diff

**Домен** `src/domain/diagram/diff.ts` (чистый, тестируемый; сравнение **по типам
компонентов**, т.к. эталонные ноды — одна-на-тип):

```ts
import type { Diagram, ComponentType } from './types';

export type NodeDiffStatus = 'match' | 'extra' | 'missing';
export type EdgeDiffStatus = 'match' | 'extra' | 'missing';

export interface DiagramDiff {
  /** Ноды пользователя: match, если тип есть в эталоне; иначе extra. keyed by node id. */
  userNodes: Record<string, 'match' | 'extra'>;
  /** Рёбра пользователя (index i → статус): match, если типовая пара есть в эталоне; иначе extra. */
  userEdges: ('match' | 'extra')[];
  /** Ноды эталона: match, если тип есть у пользователя; иначе missing. keyed by ref node id. */
  refNodes: Record<string, 'match' | 'missing'>;
  /** Рёбра эталона (index i → статус): match, если типовая пара есть у пользователя; иначе missing. */
  refEdges: ('match' | 'missing')[];
}

export function diffDiagrams(user: Diagram, reference: Diagram): DiagramDiff;
```

- Хелперы `hasType(d, t)` / `hasEdgeType(d, from, to)` (по типам, как в `validate.ts`) —
  локальные в `diff.ts` (домен не экспортирует их из `validate`; дублирование тривиальное и
  допустимое, либо вынести общий helper — на усмотрение реализации, но без изменения
  публичного API `validate`).
- Рёбра сопоставляются по типовой паре `(typeOf(from) → typeOf(to))`.

**UI** `src/features/diagram/DiffCanvas.tsx` — read-only React Flow (переиспользует паттерн
`CanvasBuilder`, но `nodesDraggable={false}`, `nodesConnectable={false}`, без палитры/удаления):

- Props: `{ diagram, positions, nodeStatus: Record<string, NodeDiffStatus>, edgeStatus: (…)[], colorMode }`.
- Ноды — кастомный read-only узел (имя + подсветка рамки/фона по статусу через существующие
  токены: `good` / `info` / приглушённый `line`-контур для `missing`). Рёбра — стиль по
  статусу (match — обычный, missing — пунктир/приглушённо, extra — info).
- Ленивый чанк (как `CanvasBuilder`).

**Встройка** в `ScenarioBuilder` (`Diagram.tsx`): блок «Пример решения» (текущий текстовый
список рёбер) заменяется на **две `DiffCanvas` бок о бок** (на мобиле — стопкой):
«Твоя схема» (позиции из уже существующего `positions`; статусы из `diff.userNodes/userEdges`)
| «Эталон» (позиции детерминированно через `gridSlot(index)`; статусы из `diff.refNodes/refEdges`).
Плюс компактная легенда (совпало / нет у тебя / лишнее). Построчный `✓/⚠/✗` отчёт выше —
без изменений. `diffDiagrams(diagram, scenario.reference)` считается при наличии `results`.

### Юнит B — стикеры на канве

- **View-состояние** (не домен): в `ScenarioBuilder` — `notes: { id: string; text: string; x: number; y: number }[]`,
  в памяти сессии (как `positions`). В `submit`/`validate`/diff/список не входят. Действия:
  `addNote()` (в свободный слот через `gridSlot` или центр), `updateNote(id, text)`,
  `moveNote(id, xy)`, `removeNote(id)`. `reset()` очищает `notes`.
- **Кастомный узел** `NoteNode` (тип `'note'`) в `CanvasBuilder`: `<textarea>` для инлайн-текста
  (`onChange` → `data.onEdit(text)`), перетаскивание (через RF), кнопка × (`data.onDelete`).
  Стиль стикера (тёплый фон, напр. amber-tint, скруглённый), без ручек-`Handle` (стикеры не
  соединяются).
- **`CanvasBuilder`**: `nodeTypes = { component, note }` (модульного уровня). RF-массив нод =
  доменные ноды (`type:'component'`) + стикеры (`type:'note'`, id с префиксом `note-`).
  `onNodesChange` роутит по типу изменённой ноды: `position` компонента → `onMove`, стикера →
  `onMoveNote`. `onNodesDelete`/× : компонент → `onRemoveNode`, стикер → `onRemoveNote`.
  Новый пропс-набор для заметок: `notes`, `onAddNote`, `onEditNote`, `onMoveNote`, `onRemoveNote`.
  Кнопка «+ Заметка» рядом с палитрой (в canvas-ветке `ScenarioBuilder`).
- Стикеры только на канве.

### a11y

Списочный конструктор — доступное с клавиатуры ядро (не трогаем). Diff — дополнительная
визуализация; доступный фидбэк = текстовый `✓/⚠/✗` отчёт (остаётся). Стикеры — mouse-first
аннотация (textarea доступна с клавиатуры при фокусе; × — реальный `<button>` с `aria-label`),
не часть решения; доступный путь сборки без них полон.

### Домен

Только новый чистый `src/domain/diagram/diff.ts`. `types.ts`/`validate.ts`/`edit.ts`/
`positions.ts` не меняются. Стикеры и позиции в домен не попадают.

## Тесты

- **`src/domain/diagram/diff.test.ts`** — `diffDiagrams`: нода-`match` (тип у обоих),
  нода-`extra` (тип только у пользователя), нода-`missing` (тип только в эталоне);
  ребро-`match`/`extra`/`missing` по типовой паре; детерминизм; сравнение именно по типам
  (разные id, одинаковые типы → match).
- **Канвы** (`DiffCanvas`, `NoteNode` в `CanvasBuilder`) — React Flow в jsdom не тестируем
  (нужны layout/ResizeObserver, как остальная канва); проверяются в браузере (CDP): diff
  показывает две канвы с корректной подсветкой match/extra/missing; стикер добавляется,
  текст редактируется инлайн, перетаскивается, удаляется ×; всё в тёмной/светлой теме.
- **Списочный смоук-тест** `Diagram.test.tsx` — остаётся зелёным (список — дефолтная вьюха,
  не затронут; diff-канвы рендерятся только после сабмита в canvas/report — тест списка их не
  триггерит).

## Рассмотрено и отклонено

- **Наложение эталона на одну канву** — путаница совмещённых позиций; выбран side-by-side.
- **Красный для «лишнего»** — лишнее ≠ ошибка (грейдинг пропускает альтернативы); info-цвет.
- **Персист стикеров/позиций в localStorage** — YAGNI (сам собираемый диаграмма не персистится).
- **Resize стикеров** — YAGNI; только перетаскивание + инлайн-текст.

## Критерии готовности

- После сабмита блок отчёта показывает две read-only канвы «Твоя | Эталон» с подсветкой
  match/extra/missing и легендой; построчный `✓/⚠/✗` отчёт сохранён; цвета нейтральные
  (без красного для «лишнего»).
- На канве сборки: «+ Заметка» добавляет стикер; текст редактируется инлайн; стикер
  перетаскивается и удаляется ×; стикеры не влияют на валидацию/сабмит.
- `diffDiagrams` покрыт тестами; домен/список не изменены; все существующие тесты зелёные;
  tsc и build чистые; канвы проверены в браузере (тёмная/светлая).
