# Миграция n8n: Cloud → self-hosted в Docker на маке + PR→Done в Actions — дизайн

**Дата:** 2026-08-18
**Статус:** дизайн утверждён, готов к плану

## Цель

Уйти с n8n Cloud (`bazhanau.app.n8n.cloud`, лимиты/платно) без потери автоматизации доски.
Пайплайн «карточка → In Progress → агент → PR → merge → Done» продолжает работать; при этом
закрываем существующую дыру: у «PR смержен → Done» сейчас нет фолбэка — если n8n лежит,
карточки молча застревают в In Review.

Решение — **расщепление (вариант A)**:

- **PR смержен → Done** переезжает из n8n в **нативный GitHub Actions workflow**
  (событийно, 24/7, не зависит от мака и туннеля вообще).
- **Trello → workflow_dispatch** и **comment → workflow_dispatch** переезжают в
  **self-hosted n8n в Docker на маке**, доступный извне через **ngrok** (постоянный
  бесплатный dev-домен). Страховка — существующий часовой cron в `trello-agent.yml`.

## Ключевые решения

- **Расщепить, а не портировать 1:1.** `trello.sh` уже умеет `move_card` + `comment` — PR→Done
  в Actions это ~30 строк YAML и один сабкоманд. В n8n остаётся только то, что требует
  входящих Trello-вебхуков.
- **ngrok free, постоянный dev-домен** (`*.ngrok-free.dev`): закреплён за аккаунтом навсегда,
  вебхуки регистрируем один раз. Лимиты: 1 ГБ/мес, 20k HTTP-запросов/мес, 3 эндпоинта —
  для вебхуков доски с запасом. Интерстишл-страница ngrok показывается только HTML-трафику
  браузера, на программные вебхуки не влияет; UI n8n через туннель не ходим вообще.
- **UI — только `http://localhost:5678`** (биндинг `127.0.0.1`), через туннель идут только
  вебхуки. Поэтому `N8N_SECURE_COOKIE` не трогаем.
- **`WEBHOOK_URL=https://<ngrok-домен>/`** — документированный способ сообщить n8n публичную
  базу за туннелем; `N8N_HOST` не ставим (сломал бы UI по localhost).
- **Пин версий образов**: n8n `2.36.0` (актуальный стабильный на дату спеки), ngrok — тоже пин.
  n8n прогоняет миграции SQLite на старте и downgrade не поддерживает → `latest` запрещён.
- **SQLite + именованный volume** (`n8n_data:/home/node/.n8n`): нагрузки нет, Postgres —
  лишняя движущаяся часть; bind-mount на macOS ломается на правах uid 1000.
- **`N8N_ENCRYPTION_KEY` в `.env` до первого запуска** (`openssl rand -hex 32`). Иначе n8n
  сгенерит свой внутрь volume; подмена ключа после создания кредов = креды молча перестают
  расшифровываться.
- **Порядок переключения строго «сначала выключить Cloud, потом включить локальный»** —
  единственная защита от двойного срабатывания (карточка дважды в Done, двойные комменты,
  двойной dispatch). Проверка после каждого шага через API, не на глаз.
- **Trello-токен есть на руках** (в GitHub Secrets он write-only) → просто вбиваем в
  credential локального n8n, перевыпуск не нужен, каскад «новый токен → умирают все вебхуки
  старого» не срабатывает.
- **Экспорт из Cloud не переносит секреты**: JSON воркфлоу содержит только ссылки на
  credential (id + имя) — Trello- и GitHub-креды вбиваются в локальный n8n руками.

## Архитектура

### 1. Локальный n8n: `~/docker/n8n/` (вне репозитория)

`compose.yaml` + `.env` + `.gitignore` (игнорит `.env`).

```yaml
services:
  n8n:
    image: docker.n8n.io/n8nio/n8n:2.36.0
    restart: unless-stopped
    ports:
      - "127.0.0.1:5678:5678"
    environment:
      - N8N_ENCRYPTION_KEY=${N8N_ENCRYPTION_KEY}
      - WEBHOOK_URL=https://${NGROK_DOMAIN}/
      - GENERIC_TIMEZONE=Europe/Sofia
      - TZ=Europe/Sofia
      - N8N_DIAGNOSTICS_ENABLED=false
    volumes:
      - n8n_data:/home/node/.n8n
  ngrok:
    image: ngrok/ngrok:<пин на момент реализации>
    restart: unless-stopped
    command: http n8n:5678 --url=${NGROK_DOMAIN}
    environment:
      - NGROK_AUTHTOKEN=${NGROK_AUTHTOKEN}
    depends_on:
      - n8n
volumes:
  n8n_data:
```

`.env`: `N8N_ENCRYPTION_KEY`, `NGROK_DOMAIN` (вида `xxx.ngrok-free.dev`), `NGROK_AUTHTOKEN`.

Флаг агента ngrok — `--url` (проверено на текущем образе; не `--domain`). Стартовые
env-флаги n8n (`N8N_RUNNERS_ENABLED` и т.п.) не угадываем заранее — поднимаем, читаем
`docker compose logs n8n`, добавляем ровно то, что просит образ 2.36.

В локальный n8n импортируются два воркфлоу из Cloud: **Trello → dispatch** (триггер
перемещения в In Progress + commentCard с фильтром `🤖`) и его commentCard-ветка — без
изменений логики, меняется только хостинг.

### 2. Новый workflow: `.github/workflows/trello-done.yml`

```
on: pull_request: types: [closed]
if: merged == true && startsWith(head.ref, 'trello/')
```

- Card id из имени ветки регуляркой `trello/([0-9a-f]+)-` (как в спеке 2026-07-23).
- Вызывает `trello.sh done <card-id> <pr-url>`.
- **Имя ветки в `run:` только через `env:`**, не через `${{ }}`-подстановку — защита от
  инъекции команд через имя ветки.
- Не-мержи (`merged == false`) и не-`trello/` ветки отсекаются условием — шаги не запускаются.

### 3. `trello.sh`: новый сабкоманд `done`

`cmd_done() { # $1 = card id, $2 = PR url }` поверх существующих хелперов:
`move_card "$1" "$TRELLO_DONE_LIST_ID"` + `comment "$1" "🤖 ✅ Смержено и задеплоено: $2 •
https://bazha.github.io/archmentor/"`. Ошибка move (карточка удалена/уже в Done) не роняет
шаг — как в спеке 2026-07-23, идемпотентно по смыслу.

Новый секрет репо: `TRELLO_DONE_LIST_ID` (список Done уже существует — использовался
облачным воркфлоу).

### 4. Что выключается в Cloud

- Оба Trello-воркфлоу (dispatch + commentCard) — деактивировать.
- GitHub-воркфлоу PR→Done — деактивировать; **вебхук на репо**
  (`…app.n8n.cloud/webhook/2c410993…`, events: pull_request) — удалить, он больше не нужен
  ни в каком виде (замена — нативный `on: pull_request`).

## Порядок миграции (весь риск — здесь)

1. Поднять `~/docker/n8n/`: `.env` с ключом → `docker compose up -d` → в логах
   `Editor is now accessible via: http://localhost:5678` → создать owner-аккаунт →
   `docker compose restart` → аккаунт на месте (доказывает, что volume подключён).
2. Экспортировать 2 Trello-воркфлоу из Cloud (JSON), импортировать в локальный n8n, вбить
   Trello-credential руками. Не активировать.
3. **Деактивировать** Trello-воркфлоу в Cloud → проверить снятие вебхуков:
   `GET https://api.trello.com/1/tokens/{token}/webhooks` — список пуст (или без
   n8n-cloud-адресов).
4. Активировать локальные воркфлоу → тем же запросом убедиться: вебхук(и) ровно на
   ngrok-домен, дублей на `*.app.n8n.cloud` нет.
5. Добавить `trello-done.yml` + `cmd_done` в `trello.sh` + секрет `TRELLO_DONE_LIST_ID`
   (обычный цикл: ветка → PR → merge). Деактивировать облачный PR→Done-воркфлоу, удалить
   GitHub-хук: `gh api repos/bazha/archmentor/hooks` → пусто.
6. Сквозной тест (см. Тестирование).
7. Аккаунт n8n Cloud не удалять сразу — подержать неделю выключенным как откат.

## Поток данных

- Карточка → In Progress → Trello-вебхук → ngrok → локальный n8n → фильтр →
  `workflow_dispatch` на `trello-agent.yml` → агент → PR. (Фолбэк: часовой cron.)
- Юзер-коммент (без `🤖`) на needs-info-карточке → тот же путь через commentCard-фильтр.
- PR смержен → GitHub Actions `trello-done.yml` (без n8n) → `trello.sh done` → карточка в
  Done + коммент со ссылкой на PR и сайт.

## Edge-cases

- **Мак спит / Docker не запущен** → Trello-вебхуки не доставляются событийно; ngrok-агент
  переподключается сам при старте. Страхует часовой cron `trello-agent.yml`; ответы-комменты
  могут ждать до часа. PR→Done не затронут вообще (Actions).
- **Квота ngrok исчерпана (1 ГБ / 20k req/мес)** — по докам «no additional usage beyond
  credit»; поведение при исчерпании публично не специфицировано, считаем худшее: туннель
  встаёт, отказ тихий. Деградация = тот же часовой cron; PR→Done не затронут. Этим
  вариант A и выбран.
- **Двойное срабатывание при миграции** → исключается порядком шагов 3→4 и API-проверками
  после каждого; никогда не держим активными обе копии одного воркфлоу.
- **Trello-вебхук умирает от ошибок** (Trello отключает hook после серии неответов, пока
  туннель лежал) → локальный n8n при реактивации воркфлоу перерегистрирует hook; диагностика —
  `GET /1/tokens/{token}/webhooks` (`active: false` = умер).
- **PR закрыт без мержа / не-`trello/` ветка** → условие workflow отсекает, шаги не бегут.
- **Карточка уже в Done / удалена** → move вернёт ошибку, `cmd_done` её глотает, workflow
  зелёный.
- **Rename/переезд репо** → нативный `on: pull_request` живёт в репо, ничего не ломается
  (в отличие от внешнего вебхука).

## Тестирование

1. **Персистентность**: owner-аккаунт + импортированные воркфлоу переживают
   `docker compose restart` и `down && up -d` (без `-v`!).
2. **Trello→dispatch**: тестовая карточка → In Progress → прогон в n8n Executions →
   `gh run list --workflow=trello-agent.yml` показывает свежий запуск.
3. **Comment→dispatch**: коммент без `🤖` на needs-info-карточке → ре-триггер; коммент с
   `🤖` → фильтр отсекает, dispatch нет.
4. **PR→Done**: смержить тестовый PR с веткой `trello/<id>-…` → карточка в Done + коммент
   со ссылками. Закрыть PR без мержа → карточка не тронута. Смержить обычную ветку → игнор.
5. **Контроль дублей**: `GET /1/tokens/{token}/webhooks` — только ngrok-адреса;
   `gh api repos/bazha/archmentor/hooks` — пусто. Ровно один коммент/перемещение на событие.

## Границы (v1)

Без Postgres, без VPS, без queue mode, без реверс-прокси. Закрытие PR без мержа (возврат
карточки) — вне области, как и раньше. Автозапуск Docker Desktop при логине — настройка
Docker Desktop, не спеки. Мониторинг «туннель жив» — вне v1 (деградация покрыта cron).

## Критерии готовности

- Карточка → In Progress запускает агента событийно через локальный n8n; часовой cron
  остаётся страховкой.
- Ответ-коммент пользователя ре-триггерит агента; `🤖`-комменты — нет.
- Мерж агентского PR двигает карточку в Done с комментом — **без участия n8n и мака**.
- Ни одного события не обрабатывается дважды; в Trello и GitHub нет вебхуков на
  `*.app.n8n.cloud`.
- Рестарт контейнеров не теряет ни аккаунт, ни воркфлоу, ни креды.
