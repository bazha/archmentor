# Углубление тонких концептов (Concept depth uplift) — дизайн

**Дата:** 2026-07-21
**Статус:** дизайн утверждён, готов к плану

## Цель

Каталог неоднороден по глубине: исходные SOLID + GoF (и 3 тонких архстиля) заметно беднее
недавно добавленных микросервисных паттернов и trade-offs. Довести **31 самый тонкий
концепт** до эталонной глубины — предметные, канон-точные объяснения. Только наполнение
существующих полей: схема, quiz-вопросы и код не меняются.

## Замер (обоснование)

По длине прозы (`definition`+`problem`+`solution`) и числу пунктов виден чёткий градиент:
- **Тонкие** (эта работа): SOLID (proza 475–647, tradeoffs=1, related 1–2), большинство GoF
  (proza 540–970, tradeoffs 1–2, 3 pros/2 cons), 3 архстиля (event-driven/monolith/mvc).
- **Эталон** (не трогаем): микросервисные паттерны (proza 1200–1730, 4–5 pros/cons/tradeoffs,
  4 whenToUse, диаграмма), категория trade-offs, богатые архстили (hexagonal/clean/layered/mvvm).

## Планка глубины (минимумы на концепт)

- `definition` ≥ ~300 симв.; `problem` ≥ ~350; `solution` ≥ ~450 — по существу (канон), не вода.
- `pros` ≥ 4; `cons` ≥ 3; `tradeoffs` ≥ 3; `whenToUse` ≥ 3; `whenNotToUse` ≥ 2.
- `related` ≥ 3 — осмысленные связи (обогащает Map-граф и авто-Compare-пресеты).
- `diagram` — добавить там, где её нет и она помогает пониманию (у части GoF уже есть
  `classDiagram`; SOLID и остальным — простая `classDiagram`/`flowchart` «связь/до-после»).

Канон: GoF (Gamma/Helm/Johnson/Vlissides) для паттернов, R.C. Martin для SOLID, Fowler для
архстилей. Формулировки точные и защитимые, без маркетинговой воды ради длины.

## Область (scope)

**31 концепт** (только объекты концептов, НЕ их вопросы):
- `src/content/concepts/solid.ts` (5): srp, ocp, lsp, isp, dip
- `src/content/concepts/patterns.ts` (5, seed): strategy, observer, factory-method, state, abstract-factory
- `src/content/concepts/creational.ts` (3): singleton, builder, prototype
- `src/content/concepts/structural.ts` (7): adapter, bridge, composite, decorator, facade, flyweight, proxy
- `src/content/concepts/behavioral.ts` (8): chain-of-responsibility, command, interpreter, iterator, mediator, memento, template-method, visitor
- `src/content/concepts/architecture.ts` (3): event-driven, monolith, mvc

**Вне области:** категория trade-offs, богатые архстили (hexagonal/clean-architecture/layered/mvvm),
микросервисы; quiz-вопросы (`c-*`/`ip-*`/`t-*` в тех же файлах — НЕ трогаем); `codeExample`
(рабочие примеры оставляем); схема, store/персист, UI. Изменение сложности/числа вопросов —
отдельный возможный заход.

## Принцип наполнения

- **Расширяем, не переписываем.** Существующие удачные формулировки и пункты сохраняем и
  дополняем — новые грани: нюансы применения, типичные ошибки/подводные камни (в prose
  `problem`/`solution`), дополнительные честные `tradeoffs`, недостающие `whenNotToUse`.
- **Двуязычность:** ru и en углубляются одинаково по смыслу (оба непустые, паритет длины
  списков внутри поля не требуется схемой, но по смыслу — соответствие).
- **`related`:** доводим до ≥3 реальными связями (существующие id). Взаимные ссылки
  автоматически создают Compare-пресеты «часто путают» — это желаемый побочный эффект
  (осмысленные пары, напр. state↔strategy уже есть; добавлять только защитимые).
- **`diagram`:** добавить недостающие; метки английские (поле — plain string, не Localized),
  как у существующих диаграмм; валидный Mermaid.

## Что НЕ меняем (инварианты)

- `id`, `name`, `category`, `grade`, `aka`, `tags`, `codeExample` — без изменений.
- Quiz-вопросы в этих файлах — без изменений (в т.ч. `ip-*` identify-pattern: их опции
  = имена концептов, а `name` мы не трогаем → инвариант `index.test.ts` не нарушается).
- Схема (`ConceptSchema`), store, персист, миграции, UI-компоненты (поля уже рендерятся).

## Точки изменений

- **Контент:** 6 файлов `src/content/concepts/{solid,patterns,creational,structural,behavioral,architecture}.ts`
  — углубление 31 объекта концепта.
- **Тест-гард (новый):** в `src/content/index.test.ts` — «depth-floor гард»: для КАЖДОГО
  концепта каталога (все 53) `tradeoffs.length ≥ 2 && related.length ≥ 2`. Это глобальный
  ПОЛ против тонких регрессий: сегодня его не проходят ровно 10 самых тонких (srp/ocp/lsp/
  isp/dip + strategy/observer/factory-method/state/abstract-factory) — все они В scope, так
  что гард зеленеет ровно когда уплифт выполнен. **Строгую планку ≥3/≥3 глобально НЕ ставим:**
  вне-области концепты законно сидят на 2 в одном измерении (mvvm/clean-architecture — 2
  tradeoffs; aggregator/bff/bulkhead — 2 related), их не трогаем. Строгая планка (≥3 tradeoffs,
  ≥3 related, prose-минимумы) для 31 концепта обеспечивается adversarial-верификацией и
  task-ревью, а не блэнкет-тестом.
- **README:** при необходимости — формулировка про глубину/консистентность (счётчики
  концептов/вопросов не меняются).

## Генерация (подход к реализации)

Через мульти-агентный workflow, с учётом **урока прошлого стопора** (большой structured-output
+ цепочка стадий вешала агентов):
- Генератор на концепт возвращает ТОЛЬКО углубляемые поля (`definition/problem/solution/pros/
  cons/tradeoffs/whenToUse/whenNotToUse/related/diagram?`), НЕ весь объект — меньше payload,
  код и метаданные не регенерируются.
- Вход генератора — существующий концепт (чтобы расширять, а не терять) + планка + канон-источник.
- Adversarial-верификация канона — отдельными ревьюерами с ТЕКСТОВЫМ выводом (не structured),
  читающими драфты с диска, батчами по категориям.
- Применение — контроллером: мёрж углублённых полей в существующие объекты в файлах, с
  сохранением форматирования (code/`join('\n')` не трогаем).
- Разбивка по категориям (SOLID / creational / structural / behavioral / seed-patterns / arch).

## Тестирование

- **zod-валидация на импорте** (`index.test.ts`) — поля непустые, `related`-id существуют,
  нет дублей, паритет опций у вопросов (вопросы не тронуты).
- **no-Cyrillic-in-en** (`index.test.ts`) — стережёт англ. поля.
- **Новый depth-floor гард** — `tradeoffs≥2 && related≥2` для всех 53 (пол против регресса;
  зеленеет по завершении уплифта).
- **Compare pairs / Map layout** — авто-детерминизм, новые взаимные пары появляются без правки.
- Итог: `npx tsc --noEmit && npm run test && npm run build` — зелёные; текущие 226 остаются
  зелёными, плюс depth-гард.

## Рассмотрено и отклонено

- **Добавить новые поля-секции** (pitfalls/examples/references как отдельные поля) — отклонено:
  пользователь выбрал «углубить существующие поля», без изменения схемы. Подводные камни идут
  в prose `problem`/`solution`, а не отдельным полем.
- **Трогать quiz-вопросы / код** — вне области (отдельные заходы).
- **Только SOLID (фаза 1)** — отклонено в пользу полного охвата ниже планки (~31).

## Критерии готовности

- Все 31 концепта соответствуют планке глубины (prose-минимумы, ≥3 tradeoffs, ≥3 related,
  диаграмма где уместно), канон-точны, двуязычны.
- Эталонные концепты и вне-области — без изменений; quiz/код/схема/store не тронуты.
- Depth-гард зелёный для всех 53; существующие тесты зелёные; tsc/build чистые.
