# Trello-агент: двусторонний диалог через комментарии — дизайн

**Дата:** 2026-07-23
**Статус:** дизайн утверждён, готов к плану

## Цель

Сделать карточку живым диалогом: когда агент отбивает карточку как `needs-info` (задаёт
вопросы), пользователь отвечает **комментарием в Trello**, и агент **сам возобновляет работу
над картой, читает историю комментов (включая ответ) и продолжает** — реализует или
уточняет ещё. Сейчас `needs-info`-карточки навсегда пропускаются, а агент читает только
name+desc (комменты не видит).

## Ключевые решения

- **Агент и пользователь комментят одним Trello-аккаунтом** (общий токен) → различить «кто
  написал» по автору нельзя. Различаем по **маркеру `🤖`**: все комменты агента начинаются с
  `🤖`, ответ пользователя — нет.
- **Нормализация маркера:** ВСЕ комменты агента префиксуются `🤖` (сейчас часть начинается с
  `❓`/`✅`/`⚠️`).
- **Повторный подхват:** карточка с меткой `needs-info` снова eligible, если её **последний
  `commentCard` НЕ агента** (текст не начинается с `🤖`). При claim такой карточки метка
  `needs-info` снимается, ставится `claude:wip`.
- **Агент читает комменты:** история комментов кладётся в `.trello-card.json`; промпт учитывает
  прошлый Q&A.
- **Ре-триггер — n8n на `commentCard`** (плюс существующий триггер перемещения + часовой cron).
- **Защита от петли (критично):** агент сам постит комменты; маркер `🤖` исключает их и в
  n8n-фильтре, и в правиле отбора → само-триггера нет.
- **Ответ = комментарий** (не правка описания). Документируем; вопросный коммент агента прямо
  просит ответить комментом.

## Архитектура

### 1. `.github/scripts/trello.sh`
- Константа `AGENT_MARKER="🤖"`; функция `comment()` уже есть — гарантируем, что каждый
  агентский коммент начинается с `🤖` (нормализовать `❓/✅/⚠️`-строки в finalize на `🤖 …`).
- Новый хелпер: `latest_comment_text(cardId)` → `GET /cards/{id}/actions?filter=commentCard&limit=1`
  → `.[0].data.text` (пусто, если комментов нет).
- Новый хелпер: `card_comments(cardId)` → `GET /cards/{id}/actions?filter=commentCard&limit=20`
  → массив `{text, date}` (для контекста агента; сортировка по дате, старые→новые).
- `select-and-claim` — новое правило отбора кандидата:
  - In Progress, БЕЗ `claude:wip`, И ( БЕЗ `needs-info` ИЛИ последний коммент НЕ начинается с `🤖` ).
  - Для `needs-info`-кандидатов проверяем `latest_comment_text` на префикс `🤖`.
  - Верхняя по `pos` из eligible.
  - При claim: если у карточки была `needs-info` — **снять её**; добавить `claude:wip` + коммент
    `🤖 Взял в работу…`.
  - В `.trello-card.json` добавить поле `comments` = `card_comments(id)`.
- `finalize` без изменений логики; только префиксы комментов → `🤖`.

### 2. Оркестратор-промпт (`.github/workflows/trello-agent.yml`)
- Вход `.trello-card.json` теперь содержит `comments` (прошлый диалог).
- Инструкция: «В `comments` — история: твои прошлые вопросы (начинаются с `🤖`) и ответы
  пользователя. Учти ответы. Если задача теперь ясна — реализуй. Если всё ещё нет — снова
  `needs-info` с уточняющими вопросами, и **в вопросах попроси ответить комментарием**.»
- needs-info questions-коммент (его постит finalize) — префикс `🤖`, текст просит ответить
  комментом.

### 3. n8n Filter (в UI — шаг пользователя, я распишу)
- Расширить условие: пропускать, если **(перемещение в In Progress, как сейчас)** ИЛИ
  **(`action.type == "commentCard"` И карточка в In Progress И `action.data.text` НЕ начинается
  с `🤖`)**.
- Это ре-триггерит пайплайн на ответ пользователя; агентские комменты (с `🤖`) отсеиваются →
  нет петли.

## Поток данных
Юзер пишет коммент (без `🤖`) → n8n commentCard проходит фильтр (не агент) → dispatch →
`select-and-claim` видит `needs-info`-карточку с последним не-агентским комментом → снимает
`needs-info`, claim, кладёт `comments` в json → агент читает desc + Q&A → реализует или
снова `needs-info`.

## Защита от петли
Агентские комменты начинаются с `🤖` → (а) n8n-фильтр их не пропускает; (б) правило отбора
считает такую карточку НЕ готовой к повтору. Итог: пост агента не вызывает новый прогон.

## Edge-cases
- **Ответ в описании, а не комментом:** карточка не возобновится (правило смотрит на комменты).
  Документируем: отвечать комментом. (Резюме по desc — вне области.)
- **Несколько кандидатов:** по-прежнему берём верхний по `pos` из eligible.
- **Нет комментов:** `latest_comment_text` пуст → для не-`needs-info` карточки не влияет.
- **Лишние API-вызовы** (комменты на кандидата) — приемлемо, In Progress мал.
- **Маркер в тексте юзера:** если пользователь вдруг начнёт ответ с `🤖` — будет принят за
  агента (не возобновит). Маловероятно; документируем «не начинай ответ с 🤖».

## Тестирование
`trello.sh` — bash без юнит-харнесса (как и раньше), проверка живая:
1. Завести расплывчатую карточку → агент ставит `needs-info` + `🤖`-вопросы.
2. Ответить **комментом** (без `🤖`) → n8n commentCard ре-триггерит → карточка снова взята
   (`needs-info` снят), агент видит ответ в `comments`.
3. Если ответа достаточно → PR; если нет → снова `needs-info`.
4. Проверить отсутствие петли: агентский `🤖`-коммент НЕ вызывает новый прогон.
`bash -n` + `ruby -ryaml` как синтакс-гейты.

## Границы (v1)
Только пайплайн Trello-агента (`trello.sh`, workflow-промпт, n8n-фильтр). Приложение не
трогаем. Резюме диалога по описанию, богатая многошаговая память сверх последних ~20 комментов
— вне области.

## Критерии готовности
- Ответ пользователя комментом на `needs-info`-карточку → агент возобновляет её (n8n commentCard),
  `needs-info` снимается, агент видит Q&A в `comments`.
- Агентские комменты (все с `🤖`) не вызывают повторный прогон (нет петли).
- Перемещение в In Progress работает как раньше; часовой cron-fallback цел.
- `bash -n`/`ruby -ryaml` зелёные; изменения только в пайплайне, не в приложении.
