# Автофикс агентского PR: красный CI и ревью CodeRabbit — дизайн

**Дата:** 2026-07-31
**Статус:** дизайн утверждён, готов к плану

## Цель

Замкнуть петлю ревью: когда на PR, открытом Trello-агентом, **падает CI** или **CodeRabbit
оставляет actionable-замечания**, агент сам возвращается **на ту же ветку**, чинит, коммитит
и пушит — PR обновляется, CI перезапускается. Человек подключается, как только автопопытка по
данной причине не помогла.

Сейчас обе ситуации — тупик: карточка навсегда висит в In Review с мёртвым PR, а ревью
CodeRabbit (который уже настроен и уже пишется на каждый агентский PR) никем не читается.
PR-гейт `ci.yml`, добавленный ранее, эту дыру и создал: он умеет краснеть, но никто на это
не реагирует.

## Ключевые решения

- **Один механизм, два триггера.** «Вернуть агента на существующую ветку с фидбеком» — это
  одна машинка; красный CI и ревью CodeRabbit только по-разному её заводят и по-разному
  наполняют контекст.
- **Триггеры — нативные GitHub Actions** (`workflow_run`, `pull_request_review`), не n8n.
  Оба конца события — GitHub, поэтому n8n здесь был бы ретранслятором вебхука: лишний
  credential, лишняя точка отказа, логика вне git. Ценность n8n в этом проекте — Trello→GitHub,
  где нативного триггера нет; здесь этот аргумент не работает. `workflow_dispatch` с входами
  `branch`/`reason` сохраняется как ручной тест и как готовая точка входа, если переезд на n8n
  всё-таки понадобится (тогда меняется только блок `on:`).
- **Отдельный воркфлоу `trello-fix.yml`**, не режим внутри `trello-agent.yml`: другой отбор
  (никакого `select-and-claim`), другой checkout, другой промпт, другой финал.
- **Карточка не покидает In Review.** Возврат в In Progress означал бы, что обычный
  `select-and-claim` подхватит её как новую задачу и начнёт всё заново новой веткой.
- **Бюджет — по одной попытке на каждую причину:** один автофикс по красному CI и один по
  actionable-ревью, максимум два прогона на PR. Раздельный счёт выбран потому, что CodeRabbit
  ревьюит **каждый** агентский PR: при общем бюджете фикс по ревью почти всегда съедал бы
  единственную попытку, оставляя красный CI без реакции. Если попытка по причине не помогла —
  по этой причине сразу зовём человека, вторую причину это не блокирует.
- **Попытка заявляется ДО работы.** Реестр — комменты в PR вида `🤖 автофикс (<reason>)`;
  коммент постится первым шагом. Если считать постфактум, упавший ран не тратит попытку и
  инфраструктурный сбой крутится вечно. Это тот же приём, что уже применён в `trello.sh`
  («claim делается ДО запуска Claude»).
- **Push только через `GH_PAT`.** Пуш из-под `GITHUB_TOKEN` не перезапускает workflow — фикс
  молча остался бы непроверенным. Тот же PAT уже используется в `trello-agent.yml`.
- **Concurrency по ветке PR**, `cancel-in-progress: false`. CI-падение и ревью CodeRabbit
  прилетают почти одновременно; без сериализации два прогона по одной причине могли бы
  разойтись в реестре и запушить конфликтующие правки.
  Отдельная группа от `trello-agent`, чтобы долгий прогон по новой карточке не блокировал фикс.
- **Право возразить.** По каждому замечанию CodeRabbit агент решает сам: починить или
  обоснованно отклонить. Отказы уходят одним `gh pr comment` (тред-ответы CodeRabbit не
  требует).
- **Чинить причину, а не тест.** Зелёный CI — это гейт, а агент работает без присмотра, поэтому
  запрет на `skip`, снятие ассертов и ослабление проверок ради зелени формулируется в промпте
  явно.

## Архитектура

```
CI упал на trello/* PR  ──┐
                          ├──►  trello-fix.yml
CodeRabbit: actionable ───┘         │
                                    ├─ 1. резолв branch + reason из payload, checkout ветки (PAT)
                                    ├─ 2. номер PR по ветке; нет открытого PR → тихий выход
                                    ├─ 3. реестр в комментах PR; попытка по этой причине уже
                                    │     была → «сдался», выход
                                    ├─ 4. заявить попытку: 🤖 автофикс (ci|review)
                                    ├─ 5. собрать фидбек → .fix-context.json
                                    ├─ 6. Claude чинит на месте; npm test + tsc зелёные
                                    ├─ 7. git push через PAT → CI перезапускается сам
                                    └─ 8. возражения в PR + итог комментом в Trello-карточку
```

### 1. `.github/workflows/trello-fix.yml` (новый)

```yaml
on:
  workflow_run:         { workflows: ["CI"], types: [completed] }
  pull_request_review:  { types: [submitted] }
  workflow_dispatch:    { inputs: { branch: {required: true}, reason: {default: ci} } }

concurrency:
  group: trello-fix-${{ github.event.workflow_run.head_branch
                     || github.event.pull_request.head.ref
                     || inputs.branch }}
  cancel-in-progress: false

permissions:
  contents: read          # пуш и все gh-команды идут через GH_PAT, не через GITHUB_TOKEN
  pull-requests: read
  id-token: write         # нужен claude-code-action (OIDC)
```

**Авторизация `gh`:** во всех шагах, читающих и пишущих PR (`gh pr list/view/comment`,
`gh api`, `gh run view`), `GH_TOKEN: ${{ secrets.GH_PAT }}` — как в шаге «Open PR» существующего
`trello-agent.yml`. Комменты в PR тогда авторства владельца репозитория, а не бота, и не
требуют `pull-requests: write` у `GITHUB_TOKEN`.

**Гейт job-а** (`if:`) — дизъюнкция трёх условий по `github.event_name`:

- `workflow_run`: `conclusion == 'failure'` И `event == 'pull_request'` И
  `startsWith(head_branch, 'trello/')`. Без всех трёх фикс полезет чинить пуши в master и
  ручные прогоны CI.
- `pull_request_review`: `review.user.login == 'coderabbitai[bot]'` И
  `startsWith(pull_request.head.ref, 'trello/')` И `contains(review.body, 'Actionable comments
  posted:')` И НЕ `contains(review.body, 'Actionable comments posted: 0')`.
- `workflow_dispatch`: без условий (ручной тест).

**Шаги:**

1. **Резолв контекста** (до checkout, из payload): `branch`, `reason` (`ci` | `review`),
   `run_id` (для `workflow_run`), `review_id` (для ревью) → в `GITHUB_OUTPUT`.
2. **Checkout**: `actions/checkout@v4` c `ref: <branch>`, `token: ${{ secrets.GH_PAT }}`,
   `fetch-depth: 0`. Явный `ref` обязателен: при `workflow_run` дефолтный checkout взял бы
   master.
3. **Номер PR**: `gh pr list --head "$branch" --state open --json number,url`. Пусто → выход 0.
4. **Реестр попыток**: `gh pr view <n> --json comments` → есть ли уже коммент, начинающийся с
   `🤖 автофикс (<reason>)`. Есть → шаг 4a и выход. Комменты с **другой** причиной не
   учитываются.
   - **4a. Сдаться:** `gh pr comment` → `🤖 ⚠️ Автофикс по причине <reason> уже применялся и
     не помог — нужен человек.`; на карточке — метка `needs-human` и коммент; job завершается
     успешно.
5. **Заявить попытку**: `gh pr comment` → `🤖 автофикс (<reason>) — <ссылка на текущий ран>`.
6. **Собрать `.fix-context.json`**:
   ```json
   { "reason": "ci|review", "branch": "...", "pr": 12, "attempt": 1,
     "ciLog": "…хвост лога упавших джобов…",
     "review": { "body": "…", "comments": [ {"path":"…","line":1,"body":"…"} ] } }
   ```
   - `ci`: `gh run view <run_id> --log-failed`, обрезать до последних ~300 строк / ~20 КБ.
     При ручном запуске `run_id` берётся как последний упавший прогон CI по этой ветке.
   - `review`: тело ревью + inline-комменты именно этого ревью
     (`gh api repos/{repo}/pulls/{n}/reviews/{review_id}/comments`). У многострочных
     замечаний `line` = `null`, поэтому номер берём как `line // start_line //
     original_line`.

**Форма события подтверждена на PR #6:** строка `**Actionable comments posted: 1**` приходит
в теле **review** (`state: COMMENTED`, `user.login: coderabbitai[bot]`), а не в issue-комменте
— в issue-комменте лежит отдельный auto-generated walkthrough, который триггером не является.
Inline-замечания привязаны к id этого ревью (`pull_request_review_id`). В `.coderabbit.yaml`
профиль `chill` (меньше придирок) и `path_filters`, исключающий `docs/**`, `**/*.md`,
`src/content/locales/**` — то есть на спеко-/контент-only PR actionable-замечаний,
как правило, не будет вовсе.
7. **Claude** (`anthropics/claude-code-action@v1`, те же секреты и флаги, что в
   `trello-agent.yml`) — промпт §2.
8. **Push**: если `.fix-result.json` → `status == "fixed"` и есть новые коммиты, выставить
   remote с `GH_PAT` и `git push origin HEAD:$branch`. Нет коммитов → трактовать как
   `no-change`.
9. **Возражения**: если `rebuttals[]` непустой — один `gh pr comment` со списком
   «замечание → почему не принято».
10. **Финал в Trello** (`if: always()`): id карточки из ветки регуляркой
    `trello/([0-9a-f]+)-`, коммент через `trello.sh comment`. Шаг не роняет job при ошибке
    Trello — код уже запушен.

### 2. Промпт фикс-режима (зеркало существующего)

Ключевые отличия от промпта `trello-agent.yml`:

- Ты **уже** на ветке `<branch>`, у неё есть открытый PR #`<n>`. **Ветку не создавать, PR не
  открывать, не мержить, Trello не трогать.**
- Вход — `./.fix-context.json`.
- `reason=ci`: воспроизведи падение локально (`npm test`, `npx tsc --noEmit`) и почини
  **причину**. Запрещено: `skip`/`only`, удаление или ослабление ассертов, правка теста под
  неверное поведение, отключение проверок. Если падение не воспроизводится локально — это
  тоже результат: `status:"error"` с описанием.
- `reason=review`: по каждому пункту либо правка, либо обоснованный отказ в `rebuttals[]`
  (`{item, why}`). Молча игнорировать пункт нельзя.
- Скоуп — только этот PR; новых зависимостей не добавлять; следовать CLAUDE.md.
- Перед коммитом `npm test` и `npx tsc --noEmit` обязаны быть зелёными.
- Коммитить поверх ветки без Claude-атрибуции. **Не пушить** — пушит следующий шаг.
- Всегда записать `./.fix-result.json`:
  `{"status":"fixed"|"no-change"|"error","note":"","rebuttals":[{"item":"","why":""}]}`.

### 3. `.github/scripts/trello.sh` — две новые сабкоманды

Переиспользуют существующие хелперы (`comment`, `ensure_label`, `add_label`), логика Trello
остаётся детерминированной и вне LLM:

- `comment <cardId> <text>` — коммент на карточку (все тексты с маркером `🤖`).
- `add-label <cardId> <name> <color>` — для `needs-human` (красная); создаётся при первом
  использовании через `ensure_label`.

Больше в репозитории ничего не меняется.

### Что сознательно не делаем

- **Метка `claude:fixing` на время работы.** Косметика: `select-and-claim` читает только
  список In Progress, карточка в In Review ему невидима при любых метках. А упавший ран
  оставил бы метку висеть навсегда — ровно та проблема, которую метки и создают. Видимость
  даёт коммент в карточке.
- **Перенос карточки** куда-либо. Она остаётся в In Review весь цикл.

## Поток данных

GitHub-событие (упавший CI / ревью CodeRabbit) → гейт `if:` → резолв `branch`+`reason` →
checkout ветки (PAT) → номер PR по ветке → реестр `🤖 автофикс (<reason>)`-комментов → заявка попытки
комментом → сбор фидбека в `.fix-context.json` → Claude правит рабочее дерево и коммитит →
push (PAT) → GitHub перезапускает CI и CodeRabbit → коммент в Trello-карточку.

Границы владения: YAML владеет отбором, реестром попыток и пушем; LLM владеет только кодом и
текстом возражений; `trello.sh` владеет всеми мутациями Trello. Секреты в промпт не попадают.

## Edge-cases

- **Фикс запушен → CodeRabbit ревьюит заново.** Попытка по причине `review` уже потрачена →
  «сдался». Именно так петля и обрывается.
- **Фикс запушен → CI снова красный.** Попытка по причине `ci` потрачена → «сдался».
- **CI-падение и ревью почти одновременно.** Это две **разные** причины, каждая со своей
  попыткой, так что оба прогона законны; concurrency по ветке сериализует их, чтобы правки не
  разъехались, и второй работает уже поверх коммита первого.
- **Одна причина сработала дважды одновременно** (например, два `workflow_run` подряд) →
  очередь по ветке + реестр: второй прогон видит коммент первого и сдаётся.
- **PR закрыт/смержен, пока фикс в очереди.** `gh pr list --state open` пусто → тихий выход.
- **Ветка не `trello/*`** (обычный PR человека) → гейт отсекает; автофикс работает только по
  агентским PR.
- **`Actionable comments posted: 0`, walkthrough, nitpick-only** → гейт отсекает.
- **Ревью не от CodeRabbit** (человек) → гейт отсекает: человеческое ревью в v1 не
  автоматизируем.
- **Карточки с таким id нет** (тестовая ветка `trello/deadbeef-…`) → Trello-шаг логирует
  ошибку и не роняет job.
- **Прогон упал жёстко** (таймаут, лимит) → попытка уже заявлена комментом, поэтому не
  зациклимся; `if: always()`-шаг пишет в карточку `🤖 ⚠️ Автофикс упал, см. Actions`.
- **Claude ничего не изменил** (`no-change` или нет коммитов) → пуша нет, в PR уходят
  возражения (если есть), в карточку — итог. Попытка считается потраченной.

## Тестирование

**Ограничение порядка (важно для плана):** `workflow_run` и `pull_request_review` читают файл
воркфлоу **из ветки по умолчанию**. Пока `trello-fix.yml` живёт только на фиче-ветке, ни один
событийный сценарий не сработает. Поэтому:

- **Сначала пункт 5** (`workflow_dispatch`) — он запускается с любой ветки
  (`gh workflow run trello-fix.yml --ref <branch> -f branch=… -f reason=ci`) и проверяет всё
  тело: реестр попыток, сбор контекста, промпт, пуш, коммент в Trello.
- **Пункты 1–4 — только после мержа в master.** Каждая правка гейта `if:` требует нового
  мержа, чтобы её проверить; это осознанная цена событийных триггеров.

1. Ветка `trello/<id-реальной-тестовой-карточки>-autofix-test` с заведомо падающим тестом →
   PR → CI краснеет → `trello-fix.yml` стартует сам, чинит, пушит; CI зеленеет; в PR коммент
   `🤖 автофикс (ci)`, в карточке — итог.
2. Тот же PR, второе падение CI подряд → «сдался»: новых коммитов нет, в PR и карточке
   «нужен человек», метка `needs-human`. При этом actionable-ревью на том же PR всё ещё
   способно запустить прогон с `reason=review` — проверить, что причины считаются раздельно.
3. PR с веткой **не** `trello/*` и красным CI → воркфлоу не стартует.
4. Ревью CodeRabbit с `Actionable comments posted: 0` → не стартует; с N>0 → стартует, правки
   и/или возражения появляются в PR.
5. `workflow_dispatch` с `branch`+`reason=ci` вручную → тот же путь (проверка ручной точки
   входа).
6. `npm test` и `npx tsc --noEmit` локально зелёные — изменения затрагивают только
   `.github/`, но гоняем как обычно.

## Границы v1

Только агентские `trello/*` PR, только два триггера (красный CI, actionable-ревью
CodeRabbit), по одной попытке на причину. Не делаем: реакцию на ревью человека, авто-мерж при зелёном,
разбор ревью по severity, ожидание успеха деплоя, возврат карточки в In Progress, изменение
поведения `trello-agent.yml`.

## Критерии готовности

- Красный CI на агентском PR запускает фикс-прогон автоматически, без участия человека и без
  n8n.
- Actionable-ревью CodeRabbit на агентском PR запускает тот же прогон; неactionable-ревью — нет.
- Попытка фиксируется комментом в PR **до** работы; по каждой причине не более одной попытки
  на PR (максимум два прогона суммарно); после исчерпания причины — «нужен человек» в PR и в
  карточке + метка `needs-human`. Исчерпание одной причины не блокирует другую.
- Фикс уходит в ту же ветку тем же PR (новых веток и PR не появляется) и пушится PAT-ом, так
  что CI перезапускается.
- По каждому замечанию CodeRabbit в PR видно либо правку, либо обоснование отказа.
- Карточка всё время остаётся в In Review; сбой Trello-шага не роняет прогон.
- Не-агентские PR и пуши в master автофикс не трогает.
