# Trello-очередь задач → автономный агент → PR — дизайн

**Дата:** 2026-07-22
**Статус:** дизайн утверждён, готов к плану

## Цель

Превратить Trello-список в очередь задач для Claude Code: пользователь кладёт карточку в
список **In Progress**, локальный планировщик раз в 10 минут это замечает, берёт карточку,
делает задачу **на отдельной ветке**, открывает **PR** и двигает карточку в **In Review** со
ссылкой на PR. Человек ревьюит и мержит/деплоит сам. Код в `master`/прод без человека не
попадает.

Это операционная обвязка вокруг Claude Code + Trello REST API, **не код приложения**. Живёт
вне репозитория (`~/.claude-work/trello-agent/`); работает над репозиторием archmentor.

## Ключевые решения

- **Граница автономности: ветка + PR → ревью человека.** Никакого авто-мержа/деплоя в v1.
- **Раннер: локальный cron/launchd**, интервал 10 мин. Использует уже настроенную `gh`-авторизацию
  и права на push; отдельный GitHub-токен не нужен.
- **Триггер: карточка в списке In Progress.** По завершении → In Review. Нативная связка
  Trello↔GitHub не требуется — посредник сам агент.
- **Непонятная карточка → bounce:** агент пишет уточняющие вопросы комментом, вешает метку
  `needs-info`, оставляет в In Progress, пропускает. Реализует только то, что понял чётко.
- **Лёгкий пайплайн v1:** короткая спека+план → TDD-реализация → один ревью-проход → тесты
  зелёные → PR. (Полный многосубагентный SDD — не в v1: дорого и хрупко без присмотра.)
- **Все мутации Trello — в bash-скрипте (детерминированно), не в LLM.** Claude занимается
  только кодом+PR и возвращает структурный результат; Trello-записи (claim/finalize/bounce)
  делает `poll.sh` по этому результату.
- **Одна карточка за прогон**, никакой параллельности.

## Архитектура

Каталог `~/.claude-work/trello-agent/`:

### 1. `.env` (chmod 600, вне git)
`TRELLO_KEY`, `TRELLO_TOKEN`, `TRELLO_BOARD_ID`, `TRELLO_INPROGRESS_LIST_ID`,
`TRELLO_INREVIEW_LIST_ID`, `REPO_DIR` (путь к archmentor), `POLL_INTERVAL_MIN=10`. Секрет —
доступ к доскам пользователя; никогда не коммитим, не печатаем в логи/PR/карточки.

### 2. `poll.sh` — оркестратор потока (bash + curl + jq)
Единственная точка, которая пишет в Trello. Шаги за один прогон:
1. `flock` на lockfile — если предыдущий прогон ещё идёт, выйти (нет наложений).
2. `GET /1/lists/{INPROGRESS}/cards` → список карточек.
3. Отфильтровать **кандидатов**: без меток `claude:wip` и `needs-info` (и без уже
   приклеенной ссылки на PR). Взять первую по позиции (верх списка).
4. Нет кандидата → выйти тихо.
5. **Claim:** `POST /1/cards/{id}/idLabels` (метка `claude:wip`) + коммент «🤖 взял в работу».
   Claim делается ДО запуска Claude — чтобы следующий cron-прогон не подхватил ту же карточку.
6. Запустить Claude headless (см. §3), передав `card.name`+`card.desc`+`card.id`; дождаться,
   прочитать `result.json`.
7. **Finalize по результату:**
   - `status:"pr"` → `PUT /1/cards/{id}?idList={INREVIEW}`, снять `claude:wip`, коммент со
     ссылкой на PR.
   - `status:"needs-info"` → коммент с вопросами (из result), метка `needs-info`, снять
     `claude:wip`, карточка остаётся в In Progress (но теперь скипается по метке).
   - `status:"error"` → коммент «прогон упал, см. лог», оставить `claude:wip` (ручной разлок)
     ИЛИ снять и вернуть в очередь — по флагу; v1: оставить `claude:wip` + `needs-info`, чтобы
     не зациклиться.
8. Всё в лог `runs/<timestamp>.log` (вне git).

Режимы: `--dry-run` (выбрать карточку и напечатать план без мутаций и без запуска Claude);
`--card <id>` (принудительно один конкретный id — для первого ручного теста).

### 3. `orchestrator.md` — промпт-инструкция агенту
Передаётся в `claude -p`. Claude НЕ трогает Trello. Его контракт:
- Вход: id/имя/описание карточки (через переменные/файл), `REPO_DIR`.
- Оценить ясность ТЗ. Если недостаточно для уверенной реализации → записать
  `result.json {status:"needs-info", questions:[...]}` и завершиться (кода не писать).
- Иначе: `cd REPO_DIR`, ветка `trello/<card-id>-<slug>`, лёгкий цикл (короткая спека+план в
  `docs/superpowers/`, TDD-реализация, один ревью-проход, `npm test`+`npx tsc --noEmit`
  зелёные), коммиты без Claude-атрибуции, `gh pr create`.
- Записать `result.json {status:"pr", prUrl, branch}`.
- При падении/непроходе тестов → `result.json {status:"error", note}` (PR не открывать).
- Ветку не мержить, не деплоить.

### 4. Запуск headless и права
`claude -p "$(cat orchestrator.md)"` c неинтерактивным permission-режимом (напр.
`--permission-mode acceptEdits` + узкий allowlist на нужные инструменты). Осознанный
компромисс: агент правит файлы без подтверждений — **страхует ревью-гейт PR** (в master/прод
без человека ничего не едет). Секреты Trello в окружение Claude не передаём (они нужны только
`poll.sh`).

### 5. Cron/launchd
Строка cron: запуск `poll.sh` каждые 10 минут. Это шаг, который применяет пользователь у себя
(я дам готовую строку и краткую инструкцию по установке). До включения cron — **ручной
dry-run и один боевой прогон по `--card`**.

## Trello-конвенция (минимум)
Два списка на доске: **In Progress** (триггер) и **In Review**. Метки `claude:wip` и
`needs-info` агент/скрипт создаст при первом запуске (или пользователь создаст заранее).
Ничего связывать с GitHub не нужно.

## Поток данных
Trello REST (`poll.sh`) → выбор+claim → `claude -p` (код на ветке, `result.json`) →
`poll.sh` finalize (Trello move/comment/label + PR-ссылка). Границы: bash владеет всеми
Trello-мутациями; LLM владеет только кодом и PR; секреты — только в `poll.sh`-окружении.

## Тестирование
Это скрипты-обвязка, а не модуль приложения — «тесты» здесь:
- `poll.sh --dry-run` на реальной доске: печатает выбранную карточку и план действий, без
  мутаций → проверяем выбор/фильтрацию.
- Ручной боевой прогон `poll.sh --card <id>` на **тестовой карточке** с понятным мелким ТЗ →
  проверяем весь путь: claim → ветка → PR → карточка в In Review со ссылкой.
- Ручной прогон на заведомо расплывчатой карточке → проверяем bounce (вопросы + `needs-info`).
- Юнит-проверка bash-хелперов выбора кандидата (фильтрация меток) — если удобно, через
  `bats` или простой assert-скрипт; иначе покрывается dry-run.
Только после зелёных ручных прогонов — включаем cron.

## Edge-cases и надёжность
- **Двойной подхват:** `flock` + метка-замок `claude:wip` (claim до запуска Claude).
- **Залипший замок** (прогон упал с `claude:wip`): v1 — ручной разлок (снять метку). Авто-детект
  «`claude:wip` старше X ч → разлок/ретрай» — во вторую итерацию.
- **Пустой список / нет кандидатов:** тихий выход.
- **Trello API ошибка/лимиты:** лог + выход, следующий прогон повторит.
- **Крупная/вне-скоуп карточка:** `needs-info` + коммент-декомпозиция, без монстро-PR.
- **Секреты:** только в `.env` (600), не в логах/PR/карточках/коммитах.

## Рассмотрено и отклонено
- **Webhook вместо polling:** мгновенно, но нужен публичный эндпоинт/бэкенд — которого нет.
- **Облачный scheduled-агент:** работает при выключенной машине, но требует клон репы + GitHub/
  Trello токены в той среде — сложнее с секретами; локальный cron имеет репу и `gh` из коробки.
- **Авто-мерж+деплой:** быстрее, но код без ревью в проде — неприемлемый риск.
- **Полный SDD на карточку в v1:** качественнее, но дорого/хрупко без присмотра; лёгкий цикл с
  теми же гейтами (тесты+ревью-проход) достаточен для старта.
- **Мутации Trello внутри LLM:** недетерминированно; вынесли в bash.

## Границы v1 (YAGNI)
Только polling; один репозиторий (archmentor); одна карточка/прогон; ветка+PR (без авто-мержа/
деплоя); без параллельности; авто-разлок залипших замков и авто-ретраи — отложено.

## Критерии готовности
- `poll.sh --dry-run` корректно выбирает верхнюю необработанную карточку In Progress и печатает
  план, ничего не меняя.
- Боевой прогон по понятной карточке: заводится ветка, тесты+tsc зелёные, открывается PR,
  карточка уезжает в In Review со ссылкой на PR, метка `claude:wip` снята.
- Расплывчатая карточка: коммент с вопросами + метка `needs-info`, кода нет, PR нет.
- Секреты только в gitignored `.env` (600); ничего чувствительного в логи/PR/карточки/коммиты.
- Cron-строка задокументирована; включается только после зелёных ручных прогонов.
- Никакого авто-мержа/деплоя; ветку мержит человек.
