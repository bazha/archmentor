# Объясняющие схемы в Library (Mermaid) — дизайн

**Дата:** 2026-07-16
**Статус:** дизайн утверждён, готов к плану

## Цель

Показывать на странице концепта (Library) объясняющую схему — визуальное «как это устроено»
(classDiagram для GoF-паттернов, flowchart для архитектурных стилей). Дёшево: схема — это
компактный текст Mermaid, лениво рендерится в браузере. Покрытие — ключевое подмножество
концептов (опционально).

## Ключевые решения

- **Механизм — Mermaid, lazy.** Схема хранится как исходник Mermaid (строка) в контенте;
  `mermaid.js` подгружается динамическим импортом только когда у концепта есть схема
  (отдельный lazy-чанк — главный бандл и страница концепта не толстеют). Осознанный
  компромисс: `mermaid` — тяжёлая зависимость, но ленивая (как React Flow).
- **Схема — не `Localized`.** Метки английские (как имена паттернов/термины по конвенции
  проекта). Один текст на концепт — дёшево; смена языка рендер не трогает.
- **Покрытие — подмножество, поле опционально.** Нет `diagram` → нет блока (грациозно).
- **Тема — встроенная mermaid** `dark`/`neutral` + прозрачный фон (дёшево; брендовый мэтч
  через `themeVariables` — возможное будущее улучшение).

## Область (scope)

- Опциональное поле `diagram` в схеме концепта + проброс в `ConceptView`.
- `ConceptDiagram` компонент (динамический импорт mermaid, тема-aware, ре-рендер при смене
  темы).
- Секция «Схема» на `ConceptPage` после «Решения».
- i18n-ключ `concept.diagram` (ru/en).
- Mermaid-схемы для ключевого подмножества концептов (GoF-паттерны + арх-стили + выборочно
  SOLID).

Вне области: build-time пре-рендер mermaid→SVG; полностью брендовая темизация через
`themeVariables`; локализация меток схем; схемы для всех 42 концептов (только подмножество).

## Архитектура по единицам

### 1. Контент — `src/content/schema.ts` + концепты

- В `ConceptSchema` добавить `diagram: z.string().min(1).optional()` — исходник Mermaid.
  Тип `Concept` получает необязательное `diagram: string`.
- Заполнить `diagram` для ключевого подмножества (в файлах `src/content/concepts/*.ts`):
  GoF-паттерны (classDiagram: Context/интерфейс/конкретные реализации и т.п.), арх-стили
  (flowchart), выборочно SOLID где схема реально помогает (напр. DIP). Метки — английские.
- Валидация: Zod проверяет опциональную непустую строку. `validateContent` не требует
  изменений (поле опционально); при желании — лёгкая проверка синтаксиса не делается (mermaid
  парсится в рантайме; невалидный источник тихо не рендерится — см. §2).

### 2. Локализация — `src/content/localize.ts`

- `ConceptView` получает `diagram?: string`; `localizeConcept` пробрасывает `c.diagram` как
  есть (не локализуется).

### 3. Рендер — `src/features/library/ConceptDiagram.tsx`

- Props: `{ source: string }`.
- Внутри `useEffect` (зависимости: `source`, тема): **динамический `import('mermaid')`**
  (mermaid попадает в отдельный lazy-чанк, грузится только при монтировании компонента, т.е.
  только у концептов со схемой).
- `mermaid.initialize({ startOnLoad: false, theme: appTheme === 'dark' ? 'dark' : 'neutral',
  securityLevel: 'strict' })`; фон прозрачный (схема на карточке `surface-raised`).
- `const { svg } = await mermaid.render(uniqueId, source)` → вставить SVG
  (`dangerouslySetInnerHTML` допустимо: источник — НАШ контент, не пользовательский ввод;
  `securityLevel: 'strict'` дополнительно санитизирует).
- Состояния: скелет/пусто во время загрузки; `try/catch` — при ошибке парсинга блок ничего
  не показывает (тихий фолбэк, не роняет страницу).
- Тема: `appTheme` из `useStore((s) => s.settings.theme)`; при смене темы `useEffect`
  перезапускается и ре-рендерит SVG под новую тему. Уникальный id рендера на инстанс
  (`useId()`), чтобы mermaid не конфликтовал при нескольких схемах/ре-рендерах.

### 4. Встройка — `src/features/library/ConceptPage.tsx`

- Новая секция «Схема» (`SectionHeading` + `<ConceptDiagram source={c.diagram} />`) сразу
  после секции «Решение», перед «Пример кода»: `{c.diagram && ( … )}`.
- i18n-ключ `concept.diagram` (ru: «Схема», en: «Diagram»), в обе карты `messages.ts`.

### 5. Зависимость

- `mermaid` — новая runtime-зависимость. Динамический импорт → отдельный lazy-чанк; не входит
  в главный бандл и в чанк страницы Library. Загружается только при открытии концепта со
  схемой. (Компромисс принят выбором «Mermaid».)

## Тесты

- **Контент** (`src/content/index.test.ts` или существующий контент-тест): где `diagram`
  задан — это непустая строка; покрыто ≥ 8 концептов (подтверждает наполнение). Zod-валидация
  проходит.
- **`ConceptDiagram`** — mermaid использует DOM-измерения и async-рендер; в jsdom не
  тестируется (как канва React Flow). Проверяется в браузере (CDP): схема рендерится в
  тёмной и светлой теме, скелет→SVG, невалидный источник не роняет страницу.
- Существующие тесты зелёные; tsc и build чистые; сборка эмитит отдельный lazy-чанк mermaid.

## Рассмотрено и отклонено

- **Build-time пре-рендер mermaid→SVG** — нет рантайм-депа, но build-машинерия
  (mermaid-cli/puppeteer) + пейн темизации SVG под dark/light. Отклонено (сложнее, не дешевле
  по итогу).
- **React Flow / ручные SVG** — пользователь выбрал Mermaid (компактнее авторинг класс-/
  flow-диаграмм).
- **Полностью брендовые `themeVariables`** — дороже; встроенных `dark`/`neutral` достаточно.
- **Локализация меток / схемы для всех 42** — вне области.

## Критерии готовности

- На страницах концептов подмножества виден блок «Схема» с корректной Mermaid-диаграммой,
  читаемой в тёмной и светлой теме; у концептов без `diagram` блока нет.
- `mermaid` грузится ленивым отдельным чанком (не в главном бандле).
- Контент-тест валидирует `diagram` где задан (≥ 8 концептов); все существующие тесты
  зелёные; tsc и build чистые; схемы проверены в браузере (обе темы).
