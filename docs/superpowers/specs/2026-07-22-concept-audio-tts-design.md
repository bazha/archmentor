# Аудио-режим Library: «Послушать концепт» (TTS) — дизайн

**Дата:** 2026-07-22
**Статус:** дизайн утверждён, готов к плану

## Цель

Дать возможность **слушать концепт** как аудио-статью: жмёшь «▶ Слушать» на странице
концепта в Library — приложение проговаривает прозу (определение → проблема → решение →
плюсы/минусы → компромиссы → когда применять), подсвечивая читаемую секцию. Сценарий —
«глаза отдыхают / повторяю в фоне». Полностью клиентская фича, без бэкенда.

## Ключевые решения

- **Движок — Web Speech API** (`window.speechSynthesis`), встроенный в браузер. Ноль
  инфраструктуры, бесплатно, работает на статическом хостинге (GitHub Pages). Качество
  голоса зависит от ОС юзера — осознанный компромисс против облачного TTS (нужен ключ +
  прокси-бэкенд + деньги) и пред-генерации mp3 (вес бандла + ре-генерация на каждую правку).
- **Читаем прозу без кода.** Код заменяем короткой врезкой «далее — пример кода». Браузерный
  TTS невыносимо проговаривает скобки/символы.
- **Посекционное чтение.** Одна `SpeechSynthesisUtterance` на секцию, очередь. Это даёт
  точную подсветку **и** обходит известный баг Chrome (обрыв речи после ~15 сек).
- **Плеер с подсветкой**: play/pause/stop, скорость (0.75/1/1.25/1.5), подсветка активной
  секции + авто-скролл, клик по секции = перемотка.
- **Язык чтения следует локали приложения** (`settings.lang`). Нет подходящего голоса или
  нет API → плеер не показываем, приложение не ломается.
- **Область — только `ConceptPage` в Library** («статья»). Learn/флешкарты и прочие режимы
  не трогаем.

## Область (scope)

- Модуль сборки нарратив-скрипта из полей концепта (чистая функция).
- Обёртка над `speechSynthesis` (очередь секций, голос по локали, rate, pause/resume/cancel).
- Хук состояния плеера + полоса-плеер в шапке `ConceptPage`.
- Подсветка активной секции на странице + авто-скролл + перемотка кликом.
- Graceful-деградация (нет API / нет голоса) и cleanup при уходе/смене языка.
- i18n (ru+en) для подписей плеера и вводных слов.
- Тесты: скрипт, обёртка (мок API), компонент.

**Вне области:** автоплейлист по категории; word-boundary подсветка отдельных слов;
скачивание mp3; облачные/студийные голоса; озвучка кода; озвучка на других экранах
(Learn, Interview, Daily). Это отдельные истории.

## Архитектура

Три изолированных юнита + точка интеграции.

### 1. `src/domain/tts/script.ts` — сборка нарратива

Чистая функция без зависимостей от браузера и React → тривиально тестируется.

```ts
export interface SpeechSection { id: string; label: string; text: string; }

// Принимает уже локализованный концепт (как из useConcept) + локализованные подписи.
export function buildSpeechScript(
  concept: LocalizedConcept,
  labels: SpeechLabels,   // { definition, problem, solution, codeSkipped, pros, cons, tradeoffs, whenToUse, whenNotToUse }
): SpeechSection[];
```

Порядок секций:
```
tagline
→ definition   (label «Определение.»)
→ problem      (label «Проблема.»)
→ solution     (label «Решение.»)
→ codeSkipped  (если есть code: одна секция «Далее — пример кода.», сам код НЕ читаем)
→ pros         (label «Плюсы.» + элементы через паузу)
→ cons         (label «Минусы.»)
→ tradeoffs    (label «Компромиссы.»)
→ whenToUse    (label «Когда применять.»)
→ whenNotToUse (label «Когда не стоит.», если поле есть)
```

- `id` каждой секции стабилен (`'definition'`, `'pros'`, …) — используется для подсветки на
  странице (маппинг «секция скрипта ↔ DOM-секция»).
- `text` — уже готовая к произношению строка: `label` + контент; списки склеиваются в
  предложения с точками-паузами. Пустые/отсутствующие поля пропускаются (не попадают в массив).

### 2. `src/domain/tts/speaker.ts` — обёртка над speechSynthesis

Тонкий императивный слой, изолирует все капризы Web Speech API. Без React.

- `isSpeechSupported(): boolean` — есть ли `window.speechSynthesis`.
- `getVoiceForLang(lang: 'ru' | 'en'): SpeechSynthesisVoice | null` — `getVoices()` с
  фильтром по префиксу `voice.lang` (`ru`/`en`); учитывает async-заполнение через событие
  `voiceschanged` (голоса приходят не сразу).
- Метод/класс `Speaker` с очередью:
  - `speak(sections, { rate, voice, onSectionStart, onEnd })` — ставит по одной utterance на
    секцию, на `utterance.onstart` дёргает `onSectionStart(index)`, на конце очереди `onEnd()`.
  - `pause()` / `resume()` / `stop()` (`cancel()`).
  - `speakFrom(index)` — перемотка: `cancel()` + постановка очереди начиная с секции `index`.
- Все обработчики снимаются в `stop()`; никаких висящих listener'ов.

### 3. `src/features/library/useConceptSpeech.ts` — состояние плеера (хук)

```ts
type SpeechStatus = 'unsupported' | 'idle' | 'playing' | 'paused';
```

- Держит `status`, `activeIndex` (индекс читаемой секции или `null`), `rate`.
- На маунт определяет `isSpeechSupported()` + наличие голоса под текущую локаль → если нет,
  `status = 'unsupported'` (полоса-плеер не рендерится).
- `play()` собирает скрипт (`buildSpeechScript`) и запускает `Speaker.speak`, обновляя
  `activeIndex` из `onSectionStart`.
- `pause/resume/stop/setRate/jumpTo(index)`.
- **Cleanup (критично):** `useEffect(() => () => speaker.stop(), [])` при размонтировании;
  плюс `stop()` при смене `conceptId` и при смене `settings.lang` (иначе речь продолжится
  «за кадром» после навигации/переключения языка).

### 4. Интеграция в `src/features/library/ConceptPage.tsx`

- Полоса-плеер в шапке (под заголовком концепта): **play/pause**, **stop**, селектор
  **скорости**, индикатор «секция N из M». Рендерится только если `status !== 'unsupported'`.
- Секции прозы получают `data`-якорь по `id` из скрипта. Активная секция подсвечивается
  мягким фоном (акцент coral, токен `--accent`), делаем `scrollIntoView({ block: 'nearest' })`.
- Клик по секции при активном чтении → `jumpTo(index)`.

## a11y

- Кнопки плеера с `aria-label` (play/pause/stop/скорость), состояние play/pause через
  `aria-pressed`.
- Индикатор прогресса секций — `aria-live="polite"` (не спамить: обновляем текст «секция N из M»).
- Подсветка секции — визуальная; для скринридеров саму озвучку дублировать не нужно (у них
  свой TTS). Контраст фона-подсветки проверяем под AA (проект AA-guarded).
- Управление с клавиатуры — обычные кнопки, фокус-кольца как в проекте.

## i18n — `src/i18n/messages.ts` (ru+en, паритет)

Новые ключи:
- Полоса плеера: `concept.audio.play`, `concept.audio.pause`, `concept.audio.stop`,
  `concept.audio.speed`, `concept.audio.progress` (шаблон «секция {n} из {m}»).
- Вводные слова секций: `concept.audio.section.definition`, `.problem`, `.solution`,
  `.codeSkipped`, `.pros`, `.cons`, `.tradeoffs`, `.whenToUse`, `.whenNotToUse`.

Существующий тест паритета ключей ru/en должен оставаться зелёным.

## Тесты

- **`script.test.ts`** — порядок секций; пропуск отсутствующих полей; врезка вместо кода
  (код не попадает в text); склейка списков; локализованные вводные; обе локали.
- **`speaker.test.ts`** — на мок `speechSynthesis`: очередь по секциям, `onSectionStart` по
  индексам, `rate` прокидывается, `stop`/`cancel` чистит очередь, `getVoiceForLang` фильтрует
  по префиксу и переживает пустой `getVoices()` до `voiceschanged`.
- **`ConceptPage`/хук** — рендер-тест: полоса появляется при поддержке, скрыта при
  `unsupported`; cleanup (`stop`) вызывается при unmount и при смене локали.

## Edge-cases

- `getVoices()` пуст на первый вызов → ждём `voiceschanged` (типично для Chrome).
- Chrome обрывает длинные utterance ~15с → уже решено посекционным чтением.
- Мобильный Safari требует старт речи по жесту юзера → наш `play()` вызывается из клика, ок.
- Смена локали во время чтения → `stop()` (продолжать чужим голосом бессмысленно).
- Уход со страницы во время чтения → `stop()` в cleanup.

## Рассмотрено и отклонено

- **Облачный TTS (ElevenLabs/OpenAI/Google):** натуральные голоса, но нужен API-ключ (нельзя
  безопасно зашить в статику), деньги за символы и прокси-бэкенд — ломает модель деплоя.
- **Пред-генерация mp3 на билде:** натуральный голос + статик-хостинг, но вес бандла,
  ре-генерация на каждую правку текста, стоимость на 53×2 языка и сложнее живой контроль
  скорости/подсветки.
- **Минимальный плеер (одна кнопка без подсветки):** быстрее, но ощущается сыро на фоне
  общего полиша приложения.
- **Автоплейлист по категории / word-boundary подсветка:** ценно, но отдельные истории —
  не в этом заходе (YAGNI).

## Критерии готовности

- На `ConceptPage` в поддерживающем браузере есть рабочая полоса-плеер; проза читается
  посекционно, активная секция подсвечивается и подскролливается, клик по секции перематывает.
- Скорость переключается на лету; pause/resume/stop работают.
- В браузере без Web Speech / без голоса под локаль плеер скрыт, страница работает штатно.
- Речь останавливается при уходе со страницы и при смене языка (нет «фонового» голоса).
- Читаемый язык совпадает с локалью приложения; код не озвучивается.
- Все новые и существующие тесты зелёные; паритет ключей ru/en сохранён; AA-контраст подсветки.
