# ArchMentor — Fill-in-the-blank exercise type

**Дата:** 2026-07-06
**Статус:** утверждён дизайн, готов к плану реализации
**Контекст:** приложение feature-complete, билингв RU/EN, на master и в проде. Квиз-движок сейчас имеет 4 типа (`identify-pattern`, `concept`, `tradeoff`, `code-smell`) — все single-select multiple-choice; UI показывает разбор после ответа, режимы переключаются пилюлями. `Question` уже локализован (`{ru,en}`). Это первая из отложенных «новых типов упражнений».

## 1. Цель и рамки

Добавить новый тип упражнения **fill-in-the-blank**: в определении концепта пропущен ключевой термин, пользователь выбирает пропущенный термин из вариантов. Тренирует **активное припоминание** — когнитивный режим, которого нет в текущем наборе (там всё узнавание). Механически укладывается в существующую MC-модель → минимум нового кода.

### Не входит (YAGNI)
- Свободный ввод текста (typing) с нечётким сопоставлением — только выбор из вариантов (переиспользует single-select движок и `correctIndex`).
- Пропуск в коде (blank токена в код-примере) — рассматривался, отложен; в этой итерации пропуск только в **определении**.
- Другие новые типы (matching, ordering, multi-select) — отдельные будущие фичи.
- Изменения схемы сверх добавления значения enum; новый персист-слайс/бэкенд.

## 2. Модель (переиспользует существующую схему `Question`)

- Единственное изменение схемы: добавить `'fill-blank'` в `QuestionTypeSchema` (`src/content/schema.ts:5` → `z.enum(['identify-pattern','concept','tradeoff','code-smell','fill-blank'])`).
- Вопрос fill-blank — обычный `Question`: `prompt` (Localized) = определение концепта с одним ключевым термином, заменённым на маркер `___`; `options` (LocalizedList) = 4 термина-кандидата (верный + 3 дистрактора); `correctIndex` — индекс верного; `explanation` (Localized) — почему верный термин верен и почему дистракторы нет; `conceptId` = концепт; `code` не используется.
- Двуязычность как везде: в `prompt.ru` бланкается RU-термин в RU-определении, в `prompt.en` — EN-термин в EN-определении (позиции/слова разные); `options.ru`/`options.en` выровнены по индексам, `correctIndex` общий (тот же слот в обеих локалях).
- ID: `fb-<conceptId>-1`. `category`/`grade` наследуются от концепта.

## 3. Контент (генерация через Workflow, как Фазы 2/B)

- **По 1 fill-blank на концепт → 42 новых вопроса** (полное покрытие, единообразие). Итого ~119 вопросов.
- Пайплайн: агент на концепт получает `name` + `definition` (ru+en) → выбирает один ключевой доменный термин (не служебное слово) → строит `prompt` = определение с этим термином, заменённым на `___` → 4 варианта (верный термин + 3 правдоподобных, но неверных доменных термина как дистракторы) → `explanation`. Adversarial-верификация: ровно один защитимо-верный вариант; подстановка верного термина реконструирует каноничное определение; дистракторы правдоподобны, но неверны; нет кириллицы в `en`-полях; длины `options.ru`/`options.en` равны и выровнены по индексам; `correctIndex` в диапазоне. Затем apply в новый модуль + zod-валидация (как в Фазе B).
- Контент-модуль: `src/content/fillBlank.ts` (`export const fillBlankQuestions: Question[]`), влитый в `src/content/index.ts` (в массив `questions`).

## 4. Интеграция в квиз

- Новая пилюля режима «Заполни пропуск»/«Fill the blank» в `src/features/quiz/Quiz.tsx` (`MODE_OPTIONS`, ~строка 24): `{ value: 'fill-blank', label: t('quiz.modeFillBlank') }`.
- `selectQuestions(questions, { type: 'fill-blank' }, …)` фильтрует по типу — работает без изменений; весь single-select flow (выбор варианта → мгновенный разбор → «Дальше») переиспользуется.
- **Полировка (опц., дёшево):** в prompt fill-blank визуально выделить маркер `___` (напр. подчёркнутый заполнитель), и после ответа показать определение с подставленным выбранным/верным термином. MVP может ограничиться отображением `___` как есть — разбор и так показывает полную формулировку.

## 5. i18n / схема

- `src/content/schema.ts`: добавить `'fill-blank'` в `QuestionTypeSchema` (единственное изменение схемы).
- `src/i18n/messages.ts`: добавить `quiz.modeFillBlank` (Заполни пропуск / Fill the blank) в обе локали (страж паритета ключей). Больше ключей не требуется — `prompt/options/explanation` приходят из контента.

## 7. Тестирование

- **Схема**: `QuestionSchema.parse` принимает валидный fill-blank; квиз-селектор возвращает только fill-blank при `{ type: 'fill-blank' }`.
- **Контент-валидация** (`index.test.ts`, над объединённым набором): каждый fill-blank содержит `___` в `prompt.ru` и `prompt.en`; `correctIndex` в диапазоне `options`; длины `options.ru`/`options.en` равны; существующие стражи (no-Cyrillic-in-en, unique ids, distractors — не применяется к терминам) продолжают проходить; substituted-term инвариант — опционально, гарантируется генерацией/верификацией.
- **Квиз**: режим fill-blank рендерит prompt с пропуском и 4 варианта; выбор варианта раскрывает разбор; счёт учитывает fill-blank как обычный вопрос.
- Регрессия: весь текущий набор зелёный; `tsc --noEmit` чист; сборка без предупреждений; двуязычно (RU/EN), обе темы.

## 8. Критерии готовности

- В квизе есть режим «Заполни пропуск»; вопросы показывают определение с пропуском и 4 термина; ответ раскрывает разбор; счёт корректен.
- 42 fill-blank вопроса (1/концепт), канон-корректные, двуязычные, ровно один верный вариант, без остаточных RU-плейсхолдеров в `en`.
- `tsc` чист; все тесты зелёные; сборка без предупреждений; без новых зависимостей.
