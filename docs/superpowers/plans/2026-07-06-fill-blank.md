# Fill-in-the-blank Exercise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `fill-blank` quiz exercise type — a concept definition with a key term blanked to `___`, answered by picking the missing term from options — reusing the existing multiple-choice engine, plus 42 generated bilingual fill-blank questions (one per concept).

**Architecture:** `fill-blank` is a new `QuestionType` enum value; a fill-blank question is a normal `Question` (`prompt` with `___`, `options`, `correctIndex`, `explanation`) so the entire single-select quiz UI + grading is reused. A new content module holds the questions; a new quiz mode pill filters to them. Content is generated by a coordinator-run Workflow (Phase 2) with adversarial verification, like the earlier content phases.

**Tech Stack:** React 18, TypeScript (strict), Zustand, Vitest + Testing Library, zod, bilingual i18n (`useT`).

## Global Constraints

- No new dependencies. No new persisted state, no backend. No new component/UI for answering — reuse the existing single-select flow in `src/features/quiz/Quiz.tsx`.
- Only schema change: add `'fill-blank'` to `QuestionTypeSchema` (`src/content/schema.ts:5`). A fill-blank question uses the existing `Question` shape; `code` is unused.
- Content is bilingual (`Localized`/`LocalizedList`): `prompt.ru` blanks a RU term in the RU definition, `prompt.en` blanks the EN term in the EN definition; `options.ru`/`options.en` are index-aligned; `correctIndex` is shared. English fields contain no Cyrillic (guarded by the existing `index.test.ts` "no Cyrillic in en" test). Options ru/en equal length is enforced by `validateContent` (schema.ts).
- Fill-blank `prompt` (both languages) must contain the literal blank marker `___` (three underscores).
- IDs: `fb-<conceptId>-1`. `category`/`grade` inherited from the concept; `conceptId` set.
- After every task: `npx tsc --noEmit` clean and full suite (`npm test`) green.

```ts
import { QuestionSchema } from './schema';
import { fillBlankQuestions } from './fillBlank';
import { getConcept } from './index';

describe('fill-blank questions', () => {
  it('are schema-valid fill-blank questions with a blank marker', () => {
    for (const q of fillBlankQuestions) {
      expect(() => QuestionSchema.parse(q)).not.toThrow();
      expect(q.type).toBe('fill-blank');
      expect(q.prompt.ru).toContain('___');
      expect(q.prompt.en).toContain('___');
      expect(q.options.ru.length).toBe(q.options.en.length);
      expect(q.correctIndex).toBeLessThan(q.options.ru.length);
      expect(q.conceptId && getConcept(q.conceptId), `${q.id} conceptId resolves`).toBeTruthy();
    }
  });
});
```

## Phase 2 (coordinator-run): generate all 42 fill-blank questions

Run as a Workflow after Task 1 (like the earlier content-generation phases), NOT as an implementer-subagent task. This replaces `src/content/fillBlank.ts` with one fill-blank question per concept (42 total, including strategy/singleton).

- [ ] **Step 1: Generate** — Workflow, one agent per concept: input = concept `name` + `definition.ru` + `definition.en`; output (structured) = `{ prompt_ru, prompt_en, options_ru[4], options_en[4], correctIndex, explanation_ru, explanation_en }`. Rules: `prompt_*` = the definition with exactly one key domain term replaced by `___` (not a stopword); the correct option is that term; 3 plausible-but-wrong domain-term distractors; options index-aligned ru/en; no Cyrillic in any `en` field.

- [ ] **Step 2: Adversarially verify each** — one skeptic per question (default KEEP=reject on doubt): exactly one defensible answer; substituting the correct term reconstructs the canonical definition; distractors plausible but wrong; `prompt_*` contains `___`; `options.ru`/`options.en` equal length + index-aligned; no Cyrillic in `en`. Repair failures and re-verify.

- [ ] **Step 3: Apply** — assemble the 42 verified questions into `src/content/fillBlank.ts` (`fillBlankQuestions: Question[]`, id `fb-<conceptId>-1`, type `'fill-blank'`, category/grade from the concept, conceptId set), serializing bilingual fields like the other content files.

- [ ] **Step 4: Validate + verify** — `fillBlank.test.ts` passes for all 42; `index.test.ts` full-validation + no-Cyrillic pass over the merged set; `npx tsc --noEmit` clean; `npm test` green; `npm run build` no chunk-size warning.
