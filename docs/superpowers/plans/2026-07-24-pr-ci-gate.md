# PR CI Gate — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Mostly assistant-run (add workflow, verify via a throwaway PR, set branch protection via `gh api`); the only human touchpoint is optionally doing branch protection in the GitHub UI instead of `gh`. Steps use `- [ ]` tracking.

**Goal:** Independently run `npm ci && npm test && npm run build` on every PR and block merging a red PR via branch protection.

**Architecture:** A new `.github/workflows/ci.yml` on `pull_request` (base master) running the same commands as `deploy.yml` (build = `tsc --noEmit && vite build`). Branch protection on `master` requires the `ci` check, with 0 required reviews (self-merge preserved). `deploy.yml` is untouched.

**Tech Stack:** GitHub Actions, `gh` CLI (authed as `bazha`), Node 22.

## Global Constraints

- Mirror `deploy.yml`'s runner setup: `actions/checkout@v6`, `actions/setup-node@v4` (node 22, `cache: npm`), commands `npm ci`, `npm test`, `npm run build`.
- Job id **`ci`** → this is the required status-check context name in branch protection.
- Branch protection: require check `ci`, **0 required approvals** (agent PRs are `bazha`-authored and self-merged; GitHub forbids approving your own PR, so required reviews would deadlock). `enforce_admins: false` so direct admin pushes of infra to master keep working.
- Do NOT modify `deploy.yml`.
- Gate on the workflow file: `ruby -ryaml` parse. Functional verification is a live PR.
- Commit messages: no Claude/Co-Authored-By/"Generated with" attribution.

### Task 1: Add `.github/workflows/ci.yml`

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Write the workflow**

```yaml
name: CI
on:
  pull_request:
    branches: [master]
  workflow_dispatch:
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
permissions:
  contents: read
jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test
      - run: npm run build   # tsc --noEmit && vite build
```

- [ ] **Step 2: Yaml gate**

Run: `ruby -ryaml -e "YAML.load_file('.github/workflows/ci.yml'); puts 'yaml OK'"`
Expected: `yaml OK`.

- [ ] **Step 3: Commit + push to master**

`pull_request` workflows run from the file on the **base** branch, so `ci.yml` must be on `master` to trigger on future PRs.
```bash
git add .github/workflows/ci.yml
git commit -m "ci: run test + build on pull_request (PR gate)"
git push origin master
```

### Task 2: Verify CI fires green on a PR (assistant, via `gh`)

- [ ] **Step 1: Create a throwaway PR**

```bash
git switch -c ci-gate-smoke
printf '\n' >> README.md          # trivial no-op change
git add README.md && git commit -m "chore: ci gate smoke test"
git push -u origin ci-gate-smoke
gh pr create --base master --head ci-gate-smoke --title "CI gate smoke test" --body "Throwaway — verifies the ci check runs. Will be closed."
```

- [ ] **Step 2: Watch the `ci` check**

```bash
gh pr checks ci-gate-smoke --watch
```
Expected: a check named **`ci`** (may display as "CI / ci") runs `npm ci`/`test`/`build` and passes.

- [ ] **Step 3: Clean up the throwaway PR**

```bash
gh pr close ci-gate-smoke --delete-branch
git switch master
```

### Task 3: Enable branch protection requiring `ci`

Choose ONE: `gh api` (assistant runs) or the GitHub UI (user).

- [ ] **Step 1a: Via `gh api` (assistant)**

```bash
gh api -X PUT repos/bazha/archmentor/branches/master/protection --input - <<'JSON'
{
  "required_status_checks": { "strict": false, "contexts": ["ci"] },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null
}
JSON
```
This requires a green `ci` check to merge a PR, requires no reviews, lets admins push directly (infra), and adds no push restrictions. Reversible: `gh api -X DELETE repos/bazha/archmentor/branches/master/protection`.

- [ ] **Step 1b (alternative): GitHub UI (user)**

Repo → **Settings → Branches → Add branch ruleset / protect `master`**:
- ✅ Require status checks to pass → search & select **`ci`**.
- Require approvals: **0** (leave off).
- Leave "Restrict who can push" / "Require PR before merging" **off** (variant "CI-only").

- [ ] **Step 2: Confirm protection is set**

```bash
gh api repos/bazha/archmentor/branches/master/protection --jq '.required_status_checks.contexts, .required_pull_request_reviews'
```
Expected: contexts include `ci`; `required_pull_request_reviews` is null/absent.

### Task 4: Confirm the gate blocks a red PR

- [ ] **Step 1: Open a deliberately-failing PR**

```bash
git switch -c ci-gate-redcheck
# introduce a failing test or a tsc error, e.g. a bad type:
printf 'export const _ciGateBad: number = "x";\n' > src/__ci_gate_bad.ts
git add src/__ci_gate_bad.ts && git commit -m "chore: ci gate red check (temporary)"
git push -u origin ci-gate-redcheck
gh pr create --base master --head ci-gate-redcheck --title "CI gate red check" --body "Throwaway — must be BLOCKED by ci. Will be closed."
```

- [ ] **Step 2: Verify `ci` fails and merge is blocked**

```bash
gh pr checks ci-gate-redcheck --watch   # expect ci = fail (tsc error via build)
gh pr view ci-gate-redcheck --json mergeStateStatus -q .mergeStateStatus   # expect BLOCKED
```
Expected: `ci` red; `mergeStateStatus` = `BLOCKED` (merge button disabled).

- [ ] **Step 3: Clean up**

```bash
gh pr close ci-gate-redcheck --delete-branch
git switch master
```
